---
title: Why Agentic Systems Need Ontologies
speaker: Frank Coyle, UC Berkeley
video: https://youtu.be/Sir59K8ZDPU
---
The talk traces two separate lineages — agents and ontologies — and argues that today's agentic AI is really the convergence of the two: a probabilistic, LLM-driven loop paired with a formal, symbolic representation of a domain. Agents trace back to early AI figures like McCarthy, Selfridge, and Minsky, who defined an agent as something that perceives, decides, and acts. Ontologies trace back even further, to Aristotle's categories of being, later formalized by Quine and, in 1993, by Gruber's definition: a formal specification of a shared conceptualization — exactly what we want to hand an agent so it shares our conceptual model of a domain. This pairing is now labeled neuro-symbolic AI: neural networks (the LLM) tied to symbolic AI (rule-based systems and knowledge graphs), and the talk's central claim is that this symbolic layer is what keeps an inherently probabilistic, hallucination-prone LLM on its guardrails.

Ontologies themselves are not exotic: they are graphs of entities, their relationships, and their properties, and they arose because relational databases are too rigid — adding a new attribute means restructuring tables, whereas a graph just gets a new node or edge. Ontologies can be built top-down, with domain experts sitting down to define entities and relationships (the same approach that drove the expert-systems boom and bust of the 1980s, which failed to scale until GPUs made neural networks viable), or bottom-up, by mining real interactions like customer behavior for entities and relationships worth adding. Builders don't have to start from scratch: existing taxonomies like schema.org, FOAF (for social networks), the Dublin Core (for describing publications), and DBpedia (which underlies Wikipedia's search) already encode decades of this work.

Once an ontology exists, auxiliary technologies like RDFS and OWL let you layer inference and constraints on top of the raw graph. RDFS domain/range lets you infer, from a statement like "Bob teaches Scooter," that Bob is a teacher and Scooter is a student. OWL adds properties such as transitivity (if Sue is an ancestor of Mary and Mary of Ann, then Sue is an ancestor of Ann) and functional properties (a "has father" relation can only have one value, so two different names linked to the same child by that relation must denote the same individual). These derivations don't live in the graph itself but sit alongside it, and they're the mechanism the talk proposes using to keep agents honest.

Turning to agent loops, the talk situates today's agentic AI within Böhm–Jacopini's 1966 result that sequence, conditionals, and iteration make a language Turing-complete — agents finally have the loop piece, which is powerful but dangerous: loops can run infinitely, drift as agents talk past each other, and burn tokens and money. Walking through a Claude agent code example, the mechanics are: the LLM can't execute anything itself, only propose the next most probable tokens, so given a tool and a prompt it returns a proposed tool call with parameters; the loop checks the stop reason, and if it's "tool use," the tool actually runs. The talk's proposed intervention is to insert an ontology-backed validator right after the tool runs and before its result is trusted: Pydantic enforces the types of parameters going in at the door, and the ontology checks the plausibility of what comes back at the ledger, so agents ideally have no side effects until their output has passed through this check.

Concrete OWL constructs illustrate the kinds of errors this reasoning can catch that are hard to catch in raw text: a disjoint-properties constraint would flag a second refund issued against the same order, or a payout mistakenly routed to a support rep instead of the buyer (since customer and support-rep are disjoint classes), while an enumerated-value constraint would reject a hallucinated status like "probably shipped" when only paid, shipped, or refunded are valid. The overall recommendation is to treat ontologies as a reasoner sitting beside the agent loop — a way to impose formal guardrails on a fundamentally probabilistic process, echoing the symbolic-AI lineage the field is now revisiting with more tractable tools.
