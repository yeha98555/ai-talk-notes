---
title: When Every Second Counts: Real-Time Analytics for AI Systems
speaker: M, Apache Doris (PMC)
video: https://youtu.be/5GjDl5Y78bE
---
This talk argues that AI agents are becoming the dominant consumers of analytics systems, and that this shift forces a rethink of what "real-time" analytics infrastructure must provide.

The starting observation is about latency budgets. A single agent turn can require several retrieval calls before it produces an answer — context pulls, tool calls, scoring, then a reply. If each retrieval takes 200ms, five of them still total about a second and feel responsive; if each takes 3 seconds, the same turn balloons to 15 seconds and users abandon the session. Latency is therefore not a backend detail but a direct determinant of product experience.

The talk frames the agent era as changing analytics workloads along three axes: volume, source, and shape. Volume rises by orders of magnitude because a single agent turn can trigger many more requests than a human analyst would issue in a day. The source of queries shifts from humans clicking BI dashboards to agents firing requests programmatically, at any time. And the shape of queries changes from a few heavy multi-join analytical queries to a mix of many small point lookups, filters, keyword searches, and vector retrievals within a single interaction. Together these shifts make low latency, high concurrency, and hybrid retrieval baseline requirements rather than nice-to-haves.

Apache Doris is presented as an open-source, MPP-based real-time OLAP database with a hybrid-serving design: it can run structured SQL analytics, full-text/keyword search, and vector retrieval within a single engine and a single query, rather than requiring separate systems stitched together. It supports both loading data into internal storage for performance and querying external sources like Iceberg, Delta Lake, PostgreSQL, or Elasticsearch in place without ingestion, sitting in the modern data stack between upstream sources (databases, streams, data lakes) and downstream consumers (BI tools, AI agents, MCP servers, observability platforms like Grafana or Langfuse).

The talk organizes what's needed for agent-facing analytics into five pillars. First, fast and reliable ingestion: continuous streaming from sources like Kafka or CDC, mutable (not just append-only) data so records can be updated without losing query performance, and the ability to absorb ingestion spikes without dropping data — backed by workload/resource isolation so one tenant's load doesn't degrade others. Benchmarks shown claim up to 40x faster queries than ClickHouse under heavy update workloads. Second, sub-second queries at high concurrency, achieved via vectorized execution, a full MPP architecture for complex joins, rich secondary indexes (inverted, sort, filter), partition pruning, hot-data caching, and pipelined execution — enough, per the talk, to sustain around 10,000 QPS on a single node. Third, hybrid retrieval in one engine: combining structured filters/aggregations, full-text search with BM25 scoring, vector similarity search, and reciprocal rank fusion, so an agent doesn't need to query three separate systems (OLAP DB, search engine, vector DB) and triple its latency and failure surface. Fourth, lakehouse integration: querying data lakes directly via a multi-catalog framework (Iceberg, Delta Lake, and others), supporting Iceberg table lifecycle operations, and accelerating lakehouse queries with materialized views — avoiding data copies, staleness, and silos while keeping compute and storage scaling independently. Fifth, agent-facing serviceability: LLM-readable schemas (column comments, table descriptions, semantic tags) to improve text-to-SQL accuracy, machine-callable interfaces beyond plain SQL/JDBC such as CLI tools, skills, and MCP-style protocols, and — critically — pluggable authorization, authentication, and audit controls, since an agent with database access could otherwise perform destructive operations like truncating tables.

Benchmark results are offered on two fronts: standard analytical benchmarks (Star Schema Benchmark, TPC-DS) where Doris is shown outperforming alternatives like Snowflake, ClickHouse, and others on complex multi-table joins (with ClickHouse reportedly failing to complete some TPC-DS queries), and an "agent log" style benchmark closer to real agent workloads — logs, traces, JSON payloads — where Doris is shown ahead of OpenSearch, Elasticsearch, and PostgreSQL, particularly when search, analytical rollups, and semi-structured JSON processing are mixed together.

The talk closes by positioning Doris as a broad, actively developed open-source project (700+ contributors) with integrations across compute, visualization, and lakehouse tooling, deployable on major clouds, and points listeners to its community and documentation for further exploration.
