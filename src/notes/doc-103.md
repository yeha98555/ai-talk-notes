---
title: AI on Your Lakehouse: Context Comes in Shapes, Not Queries
speaker: Zach Blumenfeld, Neo4j
video: https://youtu.be/kRkcNOsRyYg
---
This hands-on workshop argues that once organizations have text-to-SQL and vector search working against their lakehouse, the real bottleneck isn't data access but data shape: as warehouses grow to hundreds of tables and document stores to millions of files, an agent given only similarity search and ad hoc SQL becomes "confidently wrong," missing joins, losing documents, and unable to answer estate-level questions like "what are we not covering" or "what patterns recur across everything," because proving an absence or seeing a global pattern is exactly what semantic search cannot do.

The fix demonstrated is a graph-based context layer built around Neo4j's property-graph model (nodes, relationships, properties) expressed as three reusable shapes. The first, connections, is a semantic layer over the structured warehouse: a labs tool called NeoCarta pulls only metadata (tables, columns, primary/foreign-key join paths) from BigQuery into a graph via MCP, without ETL-ing the actual rows. An agent then reads this metadata graph to construct accurate joins across look-alike tables before running text-to-SQL — a lighter alternative to full data migration, which is often blocked by scale, sync overhead, or security boundaries; Neo4j's newer "virtual graph" extends this by letting cipher queries push down directly onto the warehouse schema.

The second shape, table of contents (outline), targets unstructured documents — manuals, bulletins, recalls — that are heavily cross-linked. Rather than the typical GraphRAG pipeline of LLM entity extraction, the workshop uses a fully deterministic load: a containment tree (library → folder → document → nested sections) plus explicit "links to" edges mirroring the source documents' cross-references, with every node given a hierarchical URI. This makes ingestion idempotent, fast, and free of LLM cost, and lets an agent traverse depth-bounded subtrees or jump to a specific URI and pull everything it links to — closer to a human flipping through a table of contents than to chunk-based retrieval. A Lucene full-text index layered on top (scoped by URI prefix, with LLM-driven semantic-term expansion for cross-vendor portability) complements rather than replaces this navigation.

The third shape, themes, applies Leiden community detection (via Neo4j's Graph Data Science library) purely to the document link graph, with no LLM labeling — clusters emerge from link structure alone, annotated with a conductance score (how tightly vs. loosely interlinked) and the top-linked documents in each group. This is deliberately lighter than Microsoft's GraphRAG approach of LLM-summarized hierarchical communities: it's fully deterministic and cheap, though its quality depends on how well the source documents are already named and linked. Themes surface previously unknown groupings (e.g., all brake-related documents) and support estate-level questions about coverage gaps or systemic patterns.

All three shapes are exposed to a coding agent (Claude Code) through a skills file plus Neo4j's CLI, cipher skill, and GDS skill, which keep the agent's generated queries current rather than pulling stale Stack Overflow patterns from the open web; this text-to-cipher experience is described as far more reliable than a year ago. Demonstrated queries include grounding a single repair question by combining full-text search, tree traversal, and a warehouse join; an estate-level query that used semantic expansion and outline traversal to surface DTC codes with no documentation and documented procedures contradicted by field outcomes; and a themes-driven query correlating document clusters with work-order history to quantify coverage per theme.

Several modeling judgment calls recur throughout: relationship names are kept deliberately generic (e.g., a single "has" for all containment levels) to keep queries manageable, at the cost of some semantic granularity; whether to model entities like "part" as explicit graph nodes versus letting the agent infer them from text is domain-dependent, mattering more in tightly ontological fields like life sciences; and in this workshop the structured connections graph and the unstructured document graph are deliberately left unlinked, sacrificing deterministic cross-referencing for speed and model-agnosticism, with explicit linking left as a natural extension. The overall framing: graph isn't a replacement for vector or full-text search, but a context layer that gives agents navigable, provable structure — table of contents for local traversal, themes for global pattern discovery, and connections for warehouse-scale joins — that pure retrieval cannot provide on its own.
