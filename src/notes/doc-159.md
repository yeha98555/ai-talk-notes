---
title: The Future of Evals: From LLM as a Judge to Agent as a Judge
speaker: Aparna Dhinakaran, Arize AI
video: https://youtu.be/q2JrUKBMf0w
---
This short talk argues that as agents have grown more complex, the evaluation methods built for an earlier generation of LLM applications have stopped being sufficient — and proposes agent-as-judge as the next step alongside, not instead of, existing approaches.

Arize's vantage point comes from running evals at scale across many production teams: over 100 million evals a month, an average of 12 eval jobs per team, and top teams running upward of 3,800 distinct evaluators. The most valuable signal, the talk argues, comes not from offline evals or even standard online evals but from evals run continuously on live production traces — this is what actually surfaces what's working, catches failures, and feeds continual-learning loops. The industry broadly agrees evals matter, with leaders from Anthropic, OpenAI, and elsewhere treating them as foundational.

The problem is that the object being evaluated has changed underneath the evaluators. In 2023, systems just answered prompts. By 2024, frontier models added tool calls, reasoning, and deep research. Now teams run loops on real-world data with sub-agents kicked off on long-horizon tasks. Each jump wasn't just harder — it was a different kind of problem, and the failure modes changed accordingly. Arize's own internal agent, Alex, illustrates this: as it gained longer memory, dynamic UI generation, and the ability to search across huge trace volumes, it also began forgetting context, losing track of task completion, and getting stuck in loops. Classical LLM-as-judge evals, built around fixed rubrics and deterministic flows, weren't designed to catch these dynamic, trajectory-level failures — especially once every user interaction produces a genuinely different execution path.

The proposed answer is agent-as-judge: using an agent to evaluate an agent, enabling adaptive, dynamic analysis rather than scoring against a fixed rubric. This doesn't replace deterministic evals or classical LLM-as-judge methods — it adds a third tool suited to a different class of problem. Most teams today rely on only the first two; the talk's claim is that the future of evals requires all three together.

Arize's concrete instantiation of this idea is Signal, a long-running agent that reads in traces, discovers patterns of issues, and identifies subtle failure modes a fixed-rubric judge would never catch — such as an agent repeatedly calling the same tool in a loop or following an inefficient trajectory. Because Signal performs this deeper analysis, it can go further than flagging problems: it can open a pull request with a proposed fix.
