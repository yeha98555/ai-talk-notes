---
title: Training Agents: Live tutorial on how to fine-tune a coding agent for continual learning
speaker: Ben Burtenshaw, Hugging Face
video: https://youtu.be/rNgUoH7Wbv8
---
This is the first session in a planned series on training agents, and its central conceit is meta: rather than hand-writing training scripts, the presenters hand a coding agent (Codex) a single high-level prompt — SFT-train a small Gemma model on a specific dataset, sweep parameters via Hugging Face Jobs, track everything in Trackio, push adapters, run evals, and update the model card — and then watch the agent plan, verify, and execute the whole pipeline while a human operator supervises.

The training data is a public dataset of real agent traces captured from Mario Zechner's Pi harness running Claude Opus 4.5: multi-turn tool calls with branching, thinking steps, and tool results, scrubbed of secrets before being published. The goal isn't to build a fully capable coding agent in one shot but to take a small, already instruction-tuned Gemma model and teach it to speak the same "agent language" — emitting the right tool calls and following the same multi-turn structure as the harness — using plain SFT, with no reward functions or RL environments yet; those are planned for follow-up sessions on GRPO and RL environments.

Before spending any compute, the agent is given a contract: read the docs, resolve the model name to its actual Hugging Face ID, implement or configure a training script, run smoke tests to catch auth, formatting, or out-of-memory failures early, and only then launch a full hyperparameter sweep (learning rate, LoRA rank, sequence length) as separate HF Jobs, each logged to a shared Trackio project. This behavior is steered by a set of custom "skills" — markdown files describing how to use TRL, HF Jobs, and Trackio consistently — which the agent reads into context before acting, and which the team can keep refining based on the mistakes agents make.

A walkthrough of SFT itself grounds the automation: it is a continuation of pretraining's next-token prediction, but applied to prompt–completion pairs (traces) rather than arbitrary text, with the crucial addition of masking — using a token like -100 to zero out the loss on the user's turn so the model only learns to reproduce the assistant's completions, not the prompts. This masking, applied via a chat template and tokenizer, is presented as the one piece of mechanical understanding that using an agent to orchestrate training can't substitute for.

Because SFT is fundamentally emulation, the resulting small model can't exceed the quality of the teacher traces it's imitating, and its general capabilities may even dip; what it can do is specialize on a narrow use case (e.g., PR triage) where good traces exist, rather than become a better generalist. Trackio dashboards showed the expected signals of correct training: decreasing loss, decreasing token-prediction entropy, rising token accuracy, and a decaying learning-rate schedule, tracked separately on train and held-out splits.

For final evaluation the agent ran separate HF Jobs using Inspect AI to score HumanEval and MBPP via vLLM. The presenters flagged this as a weak point: these benchmarks are largely saturated and unlikely to correlate with a custom trace dataset, so in practice you'd want a benchmark tied to your actual target use case (to watch it improve) plus a general coding/tool-use benchmark (to confirm you haven't degraded broader capability), rather than defaulting to generic public benchmarks.

The session closes by pointing to companion resources — a short written SFT primer, the Hugging Face LLM course, TRL docs, the published agent trace, the skills repo, the training dataset, and the resulting (soon-to-be-public) model — and frames this SFT-on-traces exercise as the first of at least three planned sessions that will progressively add GRPO-style RL and full RL environments to build toward a genuinely capable, continually learning coding agent.
