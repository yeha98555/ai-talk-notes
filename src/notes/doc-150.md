---
title: Your Agent Didn't Fail. Your Harness Did.
speaker: Vinoth Govindarajan, OpenAI
video: https://youtu.be/BInpv7lGp1o
---
The talk's thesis is blunt: most production agent failures are not model failures, they are harness failures. The opening case is a "silent success" — a user asks an agent to record a refund, the assistant confirms it, the interface looks healthy, but the next turn has no durable record of the fact. A crash at least gives you a boundary and a starting point for recovery; a silent success gives you a lie, because the model stays fluent and coherent even while reasoning over a broken history.

The speaker, who works on core data and AI infrastructure at OpenAI, frames the talk around a production contract: a model proposes, the harness commits, and the receipt proves it. The model may suggest a message, tool call, edit, or command, but it is not the production boundary — the harness owns the state transition, the authority check, the ordered commit, and the receipt that survives the turn. OpenClaw's public issue tracker is used throughout as a case study purely because its harness problems are unusually visible, not as a product pitch.

A car analogy anchors the mental model: the model is the engine, and engine power alone doesn't make a production car — you also need steering, brakes, road rules, a dashboard, and a black box. A powerful model without brakes isn't autonomy, it's a liability with good acceleration. The general harness blueprint, shared across personal agents and coding agents alike, is: events enter from many surfaces (chat, webhook, timer, heartbeat); a control plane maps each event to a session key, which defines a state boundary with one active writer; a runtime calls models and tools; tools act through approvals and policies; and an audit trail becomes the run's receipt. Because the runtime is stateless, the harness must reassemble the full working set — transcript, session state, memory, policy, tool definitions — on every turn, and if one input is missing or stale, the model's answer can still sound coherent without being correct.

None of the underlying failure classes are new — timeouts, retries, idempotency, locks, ordering, state ownership are classic distributed-systems problems. What's changed is the setting: these failures now surround a probabilistic planner building dynamic plans, pulling from more event sources, and acting through more action surfaces, which makes them easier to trigger and harder to explain.

Five concrete failure shapes, each drawn from a real OpenClaw issue, illustrate the pattern. First, a state hole: a delivered reply is not the same as a remembered fact — ownership means a named system of record can replay a fact later, and storage location alone doesn't establish that. Second, overlapping writers: two correct, locally valid writes can still produce one wrong outcome under a load-modify-save race, because last-writer-wins is not a consistency model; the fix is one ordered commit path per mutable state boundary, not the elimination of concurrency. Third, dangling tool calls: a run can wait forever for a tool result that will never arrive, so every external boundary needs a deadline, a watchdog, cancellation, and a recorded terminal outcome — success, failure, timeout, or cancel. Fourth, approval drift: capability is not execution, and an approval must be a scoped execution state bound to actor, session, tool, arguments, and lifetime, with expiration that terminates rather than silently loops. Fifth, missing edge proof: a tool reporting internal success doesn't prove the user actually saw the result, so proof must be a chain — model proposal, policy decision, execution attempt, and confirmed user-visible outcome — not a single claim.

The closing recommendation is a five-question audit to run on one real production trace: what woke the run up, what state it inherited, which authority it used, what it executed, and what evidence survived. Applied back to the opening incident, the trigger was a user message, the state it inherited was exactly the broken boundary, the channel send executed and the message was delivered, but the durable turn did not survive — a gap that no better model or prompt could have fixed, only a better harness with a complete receipt. The takeaway distills to three imperatives: own the state, order the mutation, and prove the action.
