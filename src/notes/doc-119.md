---
title: 76 Malicious AI Skills Were Hiding in Plain Sight
speaker: Security Researcher, Snyk
video: https://youtu.be/6c-nH6xz8lc
---
The starting anecdote sets up the whole talk: a developer published a "skill" for an agentic coding tool that quietly handed the agent access to production credentials. This wasn't the sanctioned, just-in-time credential injection pattern that security teams design for — where an agent gets a narrowly scoped, short-lived token only for the moment it needs it. Instead the skill baked in broad, standing access, so any agent that loaded it inherited far more permission than the task required. When the security team discovered developers were casually adopting a skill like this, the reaction was alarm, because it meant a single shared artifact could silently become a backdoor into production systems.

That anecdote turns out to be one instance of a much larger pattern. Scanning the ecosystem of publicly available skills, the team found roughly 76 that contained outright malicious code or malware — not just over-permissioned or sloppily written skills, but ones deliberately built to do harm. The number matters less than what it reveals: skills, like npm packages or VS Code extensions before them, have become a new software supply chain, and that supply chain is already being targeted. Anyone who installs a skill without vetting it is effectively running unreviewed third-party code with the keys to their agent's tool access.

The underlying risk is that skills are unusually powerful vectors compared to ordinary dependencies. A malicious or careless skill doesn't just run in a sandboxed process — it can shape what an agent decides to do, what credentials it uses, and what actions it takes on a developer's or an organization's behalf. Overly permissive access compounds this: a skill that requests broad production credentials rather than scoped, temporary ones turns any compromise (malicious intent or an honest mistake) into a much bigger incident.

The implicit call to action is to treat skills the way mature engineering organizations treat open-source dependencies: scan them for malicious code before adoption, insist on least-privilege and just-in-time credential patterns rather than static broad grants, and build organizational visibility into which skills developers are actually pulling in. Without that discipline, the convenience of a thriving skills ecosystem becomes an open door — and, as the numbers here show, that door is already being walked through.
