---
title: Perception Agents
speaker: Antje Barth, Amazon AGI Lab
video: https://youtu.be/2JX6JYyQG4Y
---
The talk opens with a familiar gap: onboarding a new teammate touches five different systems — provisioning accounts, Slack, intro meetings, laptops — and while an agent can perform each individual step, nobody owns the process end to end, so the work still falls apart in the seams between applications. The claim is that we've spent the last year teaching computers to use computers — clicking, scrolling, typing, calling APIs — and gotten quite good at stringing those steps into workflows, but capability isn't the same as reliability, and without reliability there's no trust to hand agents real autonomy.

Coding is offered as the one domain where this leap from capable to trusted has actually happened, because code is verifiable: you can run it, test it, and know for sure it worked. Most knowledge work has no such unit test — did the report land, is the design on brand, did the agent get what you meant — so verification breaks down exactly where most real work lives, in the messy seams between tools.

The proposed fix borrows from how humans collaborate: two people looking at the same screen need far less explaining to reach a shared understanding than an agent working from a written prompt. Today's agents can perceive a screen and act on it, but they fire off actions and move on without watching whether the step actually succeeded, and they work in a slow, turn-based prompt-wait-respond rhythm rather than reacting in real time as a collaborator would. The talk borrows the perceive-plan-act loop from robotics as the missing structure: an agent needs to take in the screen the way a person does — the rendered layout and state, not scraped code — and act as work unfolds, not after a round trip.

This motivates "perception agents," which matter for three reasons: they close the loop on computer use by reading the rendered result to confirm their own output instead of just hoping an action worked; they need no API or backend, since they operate on the same pixels and structure a person sees, which matters because most everyday software exposes no API at all; and they accept richer input than text, letting a user point at and annotate exactly what should change rather than writing a long, lossy description.

Two open-source pieces of a "perception agent harness" are introduced. An annotation tool, built as a Chrome extension, lets a user select elements on a live page and describe changes directly (change this heading's color, double this font size), capturing precise location and style feedback that an agent can act on without back-and-forth. A verification tool lets an agent check its own work against a design-rules file, running both visual checks (on-brand colors, layout) and functional user-flow checks (walking through the app like a real user would, adding or deleting items), then producing a report of what passed and what didn't, so a person reviews outcomes rather than clicking through everything manually.

A live demo extends perception beyond the screen: two colleagues wore wearable recording devices during an in-person design discussion, had the conversation transcribed, and fed the meeting summary directly to the agent via an "apply" button, which implemented the discussed changes and immediately ran verification against the design rules to flag anything off-brand. The talk closes by framing these two components as an early, deliberately open-sourced foundation — the patterns are expected to improve as more people build on and stress-test them — with the broader goal of agents and humans sharing context to work together rather than agents just being handed more autonomous, unverified capability.
