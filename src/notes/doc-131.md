title: Engineering the Future: Real-Time, Vector-Powered Analytics with ClickHouse
speaker: Developer Advocate, ClickHouse

This talk walks through how ClickHouse, an open-source columnar OLAP database built for fast analytics over massive data volumes, has organically become infrastructure for AI and agentic workloads — and how ClickHouse itself built a public chat agent on top of its own database and MCP server.

Customers tend to arrive at ClickHouse for AI use cases in one of two ways: they already use it for analytics and start repurposing it (early adopters used it as a vector store before it was well-optimized for that, which pushed the team to add real efficiencies), or they see peers succeeding with ClickHouse for AI and follow suit. Four AI/ML-adjacent use cases recur: as a feature store — a curated, sanitized dataset used to train models, deliberately stripped of sensitive or "poisonous" data so the resulting agent doesn't learn bad behavior or leak private information; for model inference, where new, unseen data is fed in and checked for appropriate handling; for data exploration and preparation, the trimming and enrichment work that precedes training; and as a vector store, holding vectorized data (technically an array of float32 values) for similarity search — a beta feature that lets you query for vectors similar to a given one, most intuitively demonstrated with image search but equally applicable to text.

The architecture of interaction with databases is shifting. The old pattern was one user query producing one SQL statement and one result, optionally passing through a thin middleware layer for things like auth. Chat agents break this pattern: a single user question can trigger dozens of exploratory queries as the agent iteratively fetches flight data, weather data, calendar data, and more to construct an answer, and slow queries directly throttle the agent's ability to respond. This motivated ClickHouse's own reference architecture combining its MCP server, open datasets (UK house prices, NYC taxi data, flight delays), and Anthropic's Claude for the conversational layer — publicly demoed as "Agent House" (llm.clickhouse.com), which runs multi-step SQL queries against ClickHouse and auto-generates visualizations from natural-language questions.

On the observability side, both Anthropic and OpenAI use ClickHouse to monitor their own LLM products. Anthropic needed to ingest huge volumes of fast, semi-structured, on-the-fly telemetry from Claude within its own secure, air-gapped compute environment at low operational cost, and deployed ClickHouse there rather than in the cloud, relying on dynamic scaling and blob storage. OpenAI adopted ClickHouse for ChatGPT and enterprise API observability after workloads like the viral Ghibli-style image trend created sudden, massive load spikes; the team valued ClickHouse's open-source nature (they contributed pull requests back), horizontal scalability, cloud-native operation, flexible indexing for diverse query patterns, native SQL, and track record with other large-scale customers. ClickHouse applied the same pattern to instrument its own public chat agent after it came under attack shortly after launch, using OpenTelemetry and its own ClickStack observability stack.

Underpinning much of this is the ClickHouse MCP server, which implements the model context protocol to let AI models reach beyond their training data into live systems — databases, APIs, files, even smart-home devices. The original open-source local MCP server (from around January) requires manual infrastructure setup, but a fully managed version is coming to ClickHouse Cloud in private preview: turnkey enablement from the UI, OAuth authentication, fine-grained access control, and compatibility with common MCP clients, demoed both as a standalone chat interface over personal ClickHouse data and integrated directly into Claude. ClickHouse's remote MCP server has also been listed on the AWS Marketplace under AI agents and tools. Looking ahead, an "Ask AI" feature built directly into ClickHouse Cloud aims to let non-technical users — someone in marketing, say — query the database in plain English without writing SQL, governed by the same credential and access controls that protect sensitive data today.
