---
title: Realtime AI Observability and Analytics with Apache Doris — Live Demo
speaker: SelectDB
video: https://youtu.be/_OHSZTy62_w
---
This is a live, hands-on demo built around Apache Doris, stitching together three vignettes: an AI-coded number-guessing game instrumented for observability, a real-time e-commerce analytics pipeline, and a raw ingestion-throughput benchmark.

The first vignette starts from a bare workspace and a simple 1–100 guessing game. The presenter has Claude install a set of pre-built "skills" and then write the game's code, all running inside a local sandbox with auto-approved ("dangerously accept") permissions. After the game works, Claude is asked to add observability instrumentation on top of it. The resulting traces — every prompt, response, tool call, fallback, and timing — are captured in an internal observability platform (referred to as LightFuse) that is itself powered by Doris. Playing a couple of rounds of the game produces a trace view showing each guess, the elapsed time, and the reasoning path Claude took, including a case where a Python check failed and the agent fell back to another approach. The point is that both the coding agent's behavior and the end-user's in-game behavior can be captured as structured events and analyzed the same way, purely by asking the agent to inject the instrumentation rather than hand-writing logging code.

The second vignette is a real-time e-commerce example: a Go application writes users, products, orders, and shipments into PostgreSQL, which is synchronized into Doris via CDC. A data generator continuously produces events at configurable rates (e.g., ~10/sec for users and orders, ~2/sec for products), and a dashboard built on Doris refreshes every second to show live order counts and per-minute revenue. Materialized views are highlighted as the mechanism that keeps this fast under load: because Doris refreshes materialized views per-partition, a dashboard hit against yesterday's already-computed revenue returns in milliseconds without rescanning millions of rows, while only the active (current) partition needs live recomputation. The demo also shows an update made directly in Postgres propagating into a Doris query result within roughly 16 milliseconds, and a real-time join between the orders and shipments tables — something the presenter contrasts with ClickHouse, where efficient joins are harder — completing in under 50 milliseconds.

The third vignette is a raw ingestion benchmark on a single-node Doris instance, loading synthetic rows as fast as possible: throughput starts around 11 million rows per second and settles into a sustained 8–10 million rows per second range, illustrating single-node write capacity. A separate note from the earlier ingestion into Doris logs 100 million rows inserted at an average of about 9.8 million rows per second and roughly 280 MB/sec.

Taken together, the demo argues for Doris as a single real-time OLAP layer that can simultaneously power live operational dashboards fed by CDC, fast ad hoc joins across normalized tables, and an observability backend for agent traces and application logs — all under sub-second to low-millisecond query latency and very high ingest throughput.
