---
title: Citation Needed: Provenance for LLM-Built Knowledge Graphs
speaker: Daniel Chalef, Zep AI
video: https://youtu.be/H7puB0RwJMM
---
LLMs excel at pulling together data from many sources, but they do so non-deterministically — interpreting and synthesizing inputs into a summary, an extracted fact, or a structured record that may not appear verbatim anywhere in the source material. That synthesis destroys the paper trail: legal compliance often demands provenance, but it's equally useful for debugging, for judging which sources to trust, and for deciding what to delete. Zep, an enterprise agent-memory system, is built on Graffiti, an open-source temporal graph framework, and both were shaped by customers repeatedly asking two questions about retrieved facts: where did this come from, and how trustworthy is it?

The failure mode is illustrated with a healthcare example: an agent retrieves "patient has a penicillin allergy," synthesized from an EHR record, a lab PDF, and something the patient typed into an intake chatbot. If a doctor can't tell that the source was the patient's own self-report rather than a clinical record, the fact could be dangerously overweighted. The naive fix — storing a source ID on each fact — works in deterministic data warehouses but breaks down in LLM-driven context pipelines: a single fact can be synthesized from several sources, entities get merged (J. Smith and John Smith become one identity, inheriting facts from multiple places), and new data continuously invalidates old facts. An append-only log becomes unmanageable at this rate of mutation, so lineage has to be an evolving set of links that survives merges and invalidation, not a static pointer.

Graffiti's answer is to model provenance directly as a knowledge graph: source data becomes "episode" nodes, extracted entities and the edges between them form fact triples, and tracing a fact to its source is simply a graph walk. The hard part is keeping that walk correct as the graph mutates — when two entities merge, the merged entity must retain all source links from both, or lineage silently disappears; when new data contradicts an existing fact, Graffiti marks the edge invalid and records which episodes caused the mutation, rather than deleting history.

Metadata can be projected across the graph to support veracity checks at scale: tagging episodes at ingestion (e.g., "EHR-verified") propagates that tag to every entity and fact derived from them, so an agent can filter for only verified-clinical facts as it walks the graph. When a fact has multiple parent episodes with mixed verification status, the graph exposes which parents are and aren't verified, but the policy for what counts as "trustworthy enough" is left to the application: an allergy fact might require every single source to be verified given the stakes, while a different fact might tolerate partial verification — Graffiti surfaces the information, but enforcing the business rule is the agent's job.

The same lineage links solve deletion under retention policies or right-to-be-forgotten requests. If a fact was derived from three sources and only one needs to be purged, the fact survives as long as another supporting episode remains; if it was derived solely from the deleted source, it's removed too. The rule is simple precisely because the parent-child links already exist: delete a fact only when no supporting episodes remain.

In Q&A, Chalef noted that not all provenance lives in the graph itself — Zep tracks edge-weight and relevancy changes (e.g., across dozens of edges) using a separate tracing structure rather than encoding everything in Graffiti. Fact extraction on ingestion uses a single-shot LLM call to pull out entities, relationships, and candidate fact triples cheaply, followed by a deduplication and deconfliction pass that merges entities and invalidates superseded facts (his example: "Daniel loves Adidas shoes" is later invalidated by "Daniel returned the shoes and was unhappy"). Wherever possible, that dedup/deconfliction step deliberately avoids LLMs in favor of classical NLP and IR techniques — SimHash, entropy measures, and similar — for speed, cost, and determinism. Asked about the current trend toward file- and markdown-based agent memory, Chalef argued that markdown structurally breaks down for provenance: it's very hard to trace why a line changed once files are mutated, and the problem compounds in multi-agent, multi-user, multi-source enterprise settings, even though file-based memory works reasonably well for single-user, desktop-scale use cases.

The closing summary: deriving context is inherently lossy and generative, so lineage must be engineered into the data structure itself — a graph — rather than logged after the fact. Graffiti keeps source data verbatim and links every derived artifact back to it, which buys built-in compliance, a way to judge a fact's veracity from its sources, easier debugging of why a fact exists, and a principled basis for deletion. Chalef noted as an aside that this kind of graph construction and lineage tracking is computationally expensive, and that a meaningful share of Zep's engineering effort has gone into reducing its cost and latency.
