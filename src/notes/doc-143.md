---
title: From Signal to PR: Anatomy of a Self-Improving Agent
speaker: Jason Lopatecki, Arize
video: https://youtu.be/9HbzAWnKbo4
---
The talk argues that observability is shifting from a human-facing discipline — dashboards, graphs, things you click — into a machine-facing one, where telemetry becomes the exhaust that lets agents debug and fix software themselves. The speaker draws on Arize's own experience building an in-product agent (Alex, whose first version "frankly sucked") and its successor system, Signal, which tries to automate the daily grind of finding and fixing production issues.

The framing is "observability 2.0": skills built on top of observability platforms (Pyroscope, Grafana, and others) let a coding agent gather exactly the context it needs — traces, logs, error paths — the same way a human would use those skills while debugging manually. Without that telemetry, an agent is just guessing among a million possible code paths; with it, the agent can see which path the system actually took. Evals add a further layer on top of raw traces, effectively pre-processed signal the debugging agent can also consume.

A key move is inverting the classic loop: instead of a human noticing a problem and directing an agent to fix it, the agent notices first — surfacing an issue with evidence already attached before a person even looks. This shifts the job from "responder" to "reviewer," and moves the real bottleneck away from writing the fix itself toward gaining confidence that the fix is the right one to ship. Today, humans still often drive the deeper investigation once a lead is surfaced, but even that starts from a much stronger evidentiary base than before.

Structurally, the loop has three parts: a trigger (periodic or event-based, like an error), context-gathering via skills that pull down logs/traces (often as literal files, sometimes tens of megabytes, dropped into a repo alongside the code), and a harness — Cloud Code, Cursor, or similar — that combines the code path with the production evidence to produce a fix. A worked example: a canceled-stream error in Arize's own agent Alex was automatically surfaced with a one- or two-line fix already proposed, though bigger issues still typically need a human to steer the fix to completion.

The natural progression is from doing this locally on a laptop to running the same skills and harness inside a sandbox, triggered on a schedule or by production errors. In the product demo (Arize's AX SaaS platform, with Phoenix as the open-source counterpart), Signal runs continuously against a sample financial-trading agent, surfacing issues with attached trace evidence, letting users spin up an evaluator or add a case to a dataset, and optionally filing a GitHub issue. Users choose their own harness, sandbox (Arize-hosted, Daytona, or Anthropic's managed agents), and skills; many enterprise customers prefer VPC-hosted sandboxes because they don't want production data flowing to a model vendor. The platform tracks the resulting swarm of agent sessions, lets you download transcripts, and lets you resume any session locally.

On evals specifically: they're typically LLM-as-judge assessments layered onto production traces ("online evals"), usually built reactively after a specific failure mode has been observed, so it can be caught automatically next time; they can also run at scale across an entire trace dataset, functioning as a continuously running quality layer that Signal draws on alongside raw trace data.

Asked why not simply let a general coding agent connect to production data directly, the speaker's answer is that a naïve connection doesn't work well — the real engineering is in designing skills: finding the right slice of data, materializing it into a file format the harness handles well, and giving the agent composable operations (like grouping by customer/facet) rather than raw access. Done well, this lets teams log and trace orders of magnitude more than any human could review, because the volume is now consumed by agents rather than people, closing the loop toward systems that debug and improve themselves continuously.
