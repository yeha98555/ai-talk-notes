---
title: RAG or Fine-Tune? Customizing LLMs with LoRA
speaker: Keshka, Sonder
video: https://youtu.be/jZ2VErE-wIQ
---
This talk builds up LLM fundamentals from the ground up before landing on a practical framework for choosing between RAG and fine-tuning, closing with LoRA as the efficient middle path.

The first part walks through how a model actually processes text. Raw text is broken into tokens — not necessarily whole words but subword pieces, so "unbelievable" splits into "un," "believe," "able," and punctuation — using a tokenizer unique to each model family, with every token mapped to an ID in a vocabulary file. Each token is then converted into an embedding, a numerical vector that captures meaning: semantically related tokens end up close together in vector space, so "man" and "woman" cluster on a gender dimension while "king" and "queen" cluster on a royalty dimension, and this happens across hundreds or thousands of dimensions (BERT uses 768, GPT-3 uses 12,288), which is part of why these are called "large" language models. Training itself is a transformer-based, self-supervised process: the model is fed enormous amounts of text and repeatedly asked to predict a masked or next token, and through this simple task at massive scale it absorbs grammar, factual knowledge, style, and rudimentary reasoning — like someone who has read every book in a library without necessarily understanding meaning, but who can fluently continue any passage handed to them. At inference time, generation is autoregressive: the model computes a probability over its entire vocabulary for the next token, samples one (greedily or with temperature-based exploration), appends it, and repeats.

With that foundation, the talk turns to the practical question of customizing an LLM for a specific domain or task. RAG retrieves relevant facts from an external source — via search, embeddings, or a vector database — and injects them into the prompt before it reaches the model, so the LLM answers using current, traceable, company-specific information. It's the far more common approach because it's cheap, fast to update, and easy to explain by tracing responses back to source documents. Fine-tuning, by contrast, updates the pre-trained model's own weights on new data so it consistently adopts a new skill, style, or specialized domain knowledge (the talk's own example is teaching a Western-music generation model to produce Bollywood music, which requires learning instruments and structures the base model never saw). The framing offered is that RAG solves "what to say" while fine-tuning solves "how to say it," and the two are not mutually exclusive — a model can be fine-tuned for a domain-specific skill and still use RAG on top for up-to-date facts. Fine-tuning's drawback is cost: full fine-tuning updates every parameter in the model and demands significant compute (TPUs, large training runs) and data.

LoRA (Low-Rank Adaptation) is presented as the parameter-efficient fine-tuning (PEFT) technique that makes fine-tuning far more accessible. Instead of updating the full weight matrix, LoRA freezes the original pre-trained model and injects a much smaller low-rank adapter matrix, training only that adapter on the new data before merging it back in. Because the adapter is orders of magnitude smaller than the base model, training is dramatically cheaper, and multiple LoRA adapters can be trained for different styles or domains and hot-swapped on top of the same frozen base model as needed.

The closing takeaways: tokens are the basic building blocks LLMs operate on; RAG is the default choice for reliable, current factual grounding; fine-tuning is the right tool when a model needs to learn a genuinely new skill or style rather than just new facts; the two techniques are complementary rather than competing; and LoRA is the most practical way to get fine-tuning's benefits without its usual cost and data burden.
