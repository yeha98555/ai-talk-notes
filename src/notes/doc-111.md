---
title: Active Graph Agent Runtime (BabyAGI 4)
speaker: Yohei Nakajima, Untapped Capital
video: https://youtu.be/khVX_BUnEwU
---
This talk introduces ActiveGraph, an experimental open-source runtime for building agents that grew out of three years and nine iterations of BabyAGI, plus earlier graph-based projects like Instagraph and Mindgraph. The starting observation is that long-running agents break, and the research theme has been to build the simplest thing that can improve itself.

Most agent stacks are built around the LLM: you add a response API, tools, memory, then bolt on logging afterward. ActiveGraph inverts this by building around the log. Not everything the agent does, but every change to the agent — prompts, facts, tasks — is captured as a single immutable, typed event log, which is the ground truth. This log projects a graph representing the agent's current state. Behaviors are units that react to graph changes and emit new events, which update state and can trigger further behaviors; critically, LLMs never talk to each other directly — all communication passes through this shared state, an architecture explicitly inspired by 1970s/80s blackboard systems and Kafka-style micro-workers. Policies govern how the graph can be modified: some changes (like adding a research source) can happen freely, while others (editing a master prompt, changing a fact that might contradict existing ones) require human approval or automated contradiction checks. The payoff of routing everything through a single event log is native replay, rollback, and forking — ActiveGraph is framed as a runtime, not a harness, since common agent harnesses (e.g., a ReAct loop) can be rebuilt on top of it using the same behavior/event pattern.

Context management is handled through views — essentially graph queries that pull a relevant subgraph into a behavior's context — and agents are assembled from modular "packs" (core, tool, secret, memory, identity, communication, chat) that bundle object schemas, tools, and behaviors with their own policies, so a memory pack can be swapped out without touching the rest of the agent.

Several experiments tested the approach. Using the log itself as memory — embedding the query, retrieving relevant log messages plus their structured neighbors, with no separate fact or entity extraction — performed well on LongMemEval, suggesting memory and log data substantially overlap. A practical durability win surfaced by accident: when an API key ran out mid-benchmark, ActiveGraph simply resumed from the last completed question instead of forcing a full rerun, unlike prior agents Yohei had built. Asking coding agents (e.g., Replit) to build a coding agent or a deep-research agent on top of ActiveGraph produced, without extra effort, a full auditable event log and evidence graph — a byproduct of the runtime rather than something manually engineered.

A project called Regimes explored controlled self-modification: the agent classified its own failure types on LongMemEval, was permitted to edit only the corresponding part of itself, proposed a patch, ran it through static and sandbox gate checks, then validated on held-out questions before accepting the change. Across many loops, only a handful of patches were accepted, yielding modest but statistically significant accuracy gains — and, importantly, the system retained a record of what didn't work, not just what did. Extending this, ActiveGraph Lab is a self-referential research agent that reads all of the project's own blog posts and code, proposes new experiments, asks permission to run them, writes up results, and has already found and fixed a bug in its own codebase via a merged PR, as well as discovering (and documenting) that packs are portable across repos.

A separate test used a Kaggle competition for deterministic Pokémon-trading-card-game decks, scored via Elo-style matches. Over roughly 80 iterative passes, casual tweak requests (like adding energy cards) triggered the agent to run hundreds of simulated games against reference decks and only accept a change if win rate improved with sufficient statistical confidence (a Wilson score threshold); about 20–30 of the 80 proposed changes were accepted, and the score improved gradually while the agent retained clear knowledge of which prior experiments had failed and why.

The recurring surprises were that AI coding assistants seem notably better at writing this blackboard-style, decoupled-worker architecture than at hand-rolled agent loops — plausibly because decades of training data exist on blackboard/Kafka-style systems versus the few years of data on LLM-agent patterns; that debugging naturally shifted from reading session logs to querying the ActiveGraph database directly, since everything is already cleanly typed and logged; and that packs loaded cleanly across repositories without extra plumbing.

The closing hypothesis is that long-running agents need not just a predictive world model (priors) but an experiential world model — analogous to the hippocampus maintaining something like an immutable event log that projects state and periodically feeds back into priors through replay and consolidation. Rather than agents' capability collapsing into pure reasoning as models improve, identity and competence may need to be derived from the agent's own accumulated log of experience, much as human behavior is shaped less by raw reasoning ability and more by lived history — suggesting the harness won't simply disappear as models get smarter.
