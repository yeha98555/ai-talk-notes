---
title: Why We Killed Our Multi-Agent Pipeline
speaker: Subbiah Sethuraman and Abhilash Asokan, ZS Associates
video: https://youtu.be/u6jJcIFDLE4
---
This talk recounts how a pharma-commercial analytics team built, diagnosed, and ultimately dismantled a multi-agent pipeline in favor of a single reasoning agent guided by a knowledge graph.

The domain is pharma commercial analytics, where analysts follow a four-step loop: detect a signal (say, a drop in a doctor's prescriptions), diagnose why it happened (a competitor drug, reduced payer coverage, weak field-rep engagement), decide on an action (send more reps, address coverage), and project the outlook. The team tried to mimic this loop with a pipeline of specialized agents — signal detection, source localization, driver attribution, and synthesis — coordinated by an orchestrator. The system produced plausible-looking reports, but on inspection each agent got its own local fact right while nobody owned the end-to-end picture: the driver-attribution agent correctly identified that a payer had downgraded coverage, but the synthesis agent, having lost that context in the handoff, recommended sending more reps instead of addressing insurance coverage — so the action, and therefore the outlook, was wrong even though every intermediate fact was correct.

Three root causes emerged. First, a language model was being used to detect signals — a purely statistical, deterministic task — when it should only have been used to investigate them. Second, context was leaking at every agent-to-agent handoff, so downstream agents lost the weight and nuance of upstream findings. Third, none of the agents shared real business-domain knowledge — metrics like prescription counts and their causal relationships — so agents inferred relationships from raw tables that often didn't actually hold.

Rather than redesigning the multi-agent topology from scratch, the team instead opened a blank directory, gave Claude Code just bash and database access, fed it a real signal, and watched how a single coding agent naturally solved the same problem. Three lessons came from that observation. Signal detection was pulled out entirely into a deterministic, rule-based pipeline — statistical methods, thresholds, and prioritization run before any agent starts — with the agent waking up only once a signal lands on a queue, so its job becomes purely investigation. The distributed reasoning across separate agents was consolidated into one agent that owns judgment end to end; parallelism was kept, but only for delegating bounded sub-investigations (e.g., checking rep activity in one region) to dynamically spawned sub-agents, never for splitting reasoning itself. And to fix the missing domain context, the team worked with in-house pharma domain experts to build a knowledge graph mapping entities (geography, payers, accounts, brands) and their relationships to KPIs and sub-KPIs.

The knowledge graph is treated not as a lookup table but as a control plane: it defines which paths and hypotheses the agent is allowed to evaluate at each stage. For "where" (source localization), the graph enumerates the dimensions a decline could be concentrated in — region, territory, payer, account, or combinations thereof. For "why" (driver attribution), the graph's KPI relationships determine which causal hypotheses are admissible. The agent runs a loop: start at an entity, inspect the graph neighborhood, form a hypothesis from an edge, go back to the raw data to test it, and either follow the graph further if supported or back off if contradicted, repeating until it exhausts hypotheses or converges on a root cause. This bounded, graph-constrained search let the agent reproduce in about 20–30 minutes (over 50-plus turns) analysis that previously took a human analyst three to four weeks.

The closing takeaways: don't bake human organizational or process constraints into agent architecture — let the architecture be derived from how the task is actually solved; separate deterministic sub-tasks from agentic ones and never let an agent do the deterministic part; ensure a single agent owns end-to-end reasoning, even if it delegates bounded sub-tasks to tools or sub-agents; and treat a domain knowledge graph as a control plane that shapes what the agent can investigate next, not merely a data source it queries.
