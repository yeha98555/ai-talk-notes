---
title: 76 個惡意 AI Skill 就這樣大剌剌地藏在檯面上
speaker: 資安研究員，Snyk
---
這場對談的開場軼事,一位開發者發佈了一個給 agentic coding 工具用的「skill」,卻在無形中讓 agent 取得了正式環境（production）的憑證存取權。這並非資安團隊設計的那種正規、即時（just-in-time）憑證注入模式——也就是 agent 只在需要的當下取得範圍極窄、短效的 token。相反地,這個 skill 內建了寬鬆且長期有效的存取權限,使得任何載入它的 agent 都繼承了遠超任務所需的權限。當資安團隊發現開發者正在若無其事地使用這樣的 skill 時,反應是震驚,因為這意味著一個共用的產出物竟可能悄悄變成通往正式環境的後門。

這個軼事其實只是更大模式中的一個案例。在對公開可取得的 skill 生態系進行掃描後,團隊發現大約有 76 個 skill 含有徹頭徹尾的惡意程式碼或惡意軟體——不只是權限過大或撰寫草率的 skill,而是刻意設計來造成傷害的。數字本身不是重點,重點在於它揭露的事實:skill 就跟先前的 npm 套件或 VS Code 擴充功能一樣,已經成為一種新的軟體供應鏈,而這條供應鏈已經正在被鎖定攻擊。任何未經審查就安裝 skill 的人,實際上等於在執行未經審視的第三方程式碼,而且這些程式碼還握有 agent 的工具存取金鑰。

潛在的風險在於,相較於一般的相依套件,skill 是異常強大的攻擊向量。一個惡意或粗心撰寫的 skill 不只是在沙箱化的行程中執行——它能夠左右 agent 決定要做什麼、使用哪些憑證,以及代表開發者或組織採取哪些行動。過度寬鬆的存取權限更會放大這個問題:一個要求廣泛正式環境憑證、而非範圍受限之臨時憑證的 skill,會讓任何一次淪陷(不論出於惡意還是無心之過)都演變成更嚴重的事件。

這裡隱含的行動呼籲,是要求組織以對待開源相依套件的成熟做法來看待 skill:在採用前掃描是否含有惡意程式碼,堅持最小權限與即時憑證發放模式而非靜態的廣泛授權,並在組織內建立對開發者實際引入哪些 skill 的可見性。若缺乏這種紀律,一個蓬勃發展的 skill 生態系所帶來的便利性,就會變成一扇敞開的大門——而正如這裡的數字所顯示的,這扇門已經有人闖入。
