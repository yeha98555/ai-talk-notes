---
title: RAG 還是微調？用 LoRA 客製化 LLM
speaker: Keshka, Sonder
---
這場演講先從 LLM 的基礎原理講起，逐步建立起理解，最後帶出一套在 RAG 與微調之間做選擇的實務框架，並以 LoRA 作為兼顧效率的折衷方案收尾。

第一部分說明模型如何實際處理文字。原始文字先被拆解成 token——不一定是完整單字，而是子詞片段，例如「unbelievable」會被拆成「un」、「believe」、「able」與標點符號——所使用的分詞器（tokenizer）因模型家族而異，每個 token 都對應到詞彙表（vocabulary file）中的一個 ID。接著每個 token 會被轉換成 embedding，也就是能捕捉語義的數值向量：語義相近的 token 在向量空間中會彼此靠近，例如「man」與「woman」會在性別維度上聚集，而「king」與「queen」則在皇室維度上聚集，且這種關聯橫跨數百甚至數千個維度（BERT 使用 768 維，GPT-3 則使用 12,288 維），這也是為何這類模型被稱為「大型」語言模型的部分原因。訓練本身是一個基於 Transformer、自我監督的過程：模型被餵入海量文字，並反覆被要求預測被遮蔽或下一個 token，透過這個看似簡單的任務在龐大規模下運作，模型逐漸吸收了文法、事實知識、風格與初步的推理能力——就像一個讀遍圖書館所有書籍的人，未必真正理解意義，卻能流暢地接續任何一段文字。在推論階段，生成過程是自迴歸的：模型針對整個詞彙表計算下一個 token 的機率分布，依貪婪策略或溫度取樣選出一個 token，接上去後再重複這個過程。

有了這個基礎，演講接著談到如何為特定領域或任務客製化 LLM 的實務問題。RAG 透過搜尋、embedding 或向量資料庫，從外部來源檢索相關事實，並在提示送入模型前將其注入其中，讓 LLM 能運用即時、可追溯來源、與公司相關的資訊來作答。這是遠比微調更常見的做法，因為成本低、更新快，且容易透過追溯回原始文件來解釋回答依據。相對地，微調則是在新資料上更新預訓練模型自身的權重，使其穩定地展現新技能、新風格或特定領域知識（演講中舉的例子是讓一個以西方音樂訓練的音樂生成模型學會生成寶萊塢音樂，這需要學習基礎模型從未見過的樂器與結構）。演講給出的框架是：RAG 解決的是「該說什麼」，微調解決的是「該怎麼說」，兩者並非互斥——模型可以先針對特定領域技能進行微調，再疊加 RAG 以取得最新事實。微調的缺點在於成本：完整微調會更新模型的每一個參數，需要可觀的運算資源（如 TPU、大規模訓練）與資料量。

LoRA（低秩適應，Low-Rank Adaptation）被視為讓微調變得更平易近人的參數高效微調（PEFT）技術。LoRA 不更新完整的權重矩陣，而是凍結原始預訓練模型，注入一個小得多的低秩適配器矩陣，僅針對新資料訓練這個適配器，再將其合併回原模型。由於適配器的規模比基礎模型小上好幾個數量級，訓練成本因此大幅降低，且可以針對不同風格或領域訓練多個 LoRA 適配器，並在同一個凍結的基礎模型上依需求熱抽換使用。

最後的結論歸納為：token 是 LLM 運作的基本構件；RAG 是取得可靠、即時事實依據的預設選擇；當模型需要真正學會新技能或新風格、而不只是新事實時，微調才是正確工具；這兩種技術是互補而非互相競爭的關係；而 LoRA 則是在不必承擔傳統微調高昂成本與資料負擔的情況下，取得微調效益最實際的方法。
