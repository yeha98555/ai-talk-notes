---
title: 把所有資料放進知識圖譜，但別把它當 RAG 用
speaker: 講者，AI Native Dev
---
問題的起點是「控制」：agent 的輸出結果時常不一致，講者想要一種更可靠的方式，讓 agent 的行為紮根於資料。解法是把所有資料載入一個知識圖譜——其實就是一個在實體之間建立明確連結的資料庫——而不是單純的向量儲存。

關鍵的架構選擇是：打造一個看起來幾乎像 RAG 的系統，但不要把它當 RAG 使用。不同於對文字區塊做相似度搜尋、再把 top-k 結果塞進提示詞，這裡讓 agent 自己走訪圖譜中的連結，像瀏覽一份存在磁碟上、供 LLM 使用的 wiki 一樣，從一個節點跟隨連結走到下一個節點，而不是取用零散的片段。

這種以走訪（traversal）為基礎的做法，被視為在不犧牲精確度的前提下擴展上下文規模的方式：因為圖譜有索引，即使資料量遠超一般 RAG 系統所能處理的規模，搜尋仍然很快；而尋找資料之間的關係之所以快，是因為這些關係是明確儲存的，而不是在檢索當下才推論出來。這裡隱含的對比對象是標準 RAG——在標準 RAG 中，區塊之間的關係並未被建模，只有相似度被建模，因此隨著資料量增加，相關性與一致性都會下降。將知識結構化為圖譜、並讓 agent 直接在其中導航，正是用來修正最初促成整套做法的那個不一致問題。
