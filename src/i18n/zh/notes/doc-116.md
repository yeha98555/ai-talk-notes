---
title: Training Agents 2：客製化代理人的模型蒸餾實作直播教學
speaker: Ben 與 Sergio，Hugging Face
---
這是「訓練代理人」系列的第二場直播，接續前一場關於在代理人軌跡（agent traces）上做監督式微調（SFT）的內容。整個系列的架構是後訓練（post-training）：預訓練賦予模型一般語言能力與世界知識，中訓練加入程式碼等領域知識，後訓練（SFT、蒸餾、RL）則教會模型特定行為與輸出格式。蒸餾被定位為讓小型、便宜、快速的模型在特定任務上表現優異的主力方法，透過向更大或領域專精的模型學習——可用於壓縮、能力遷移與合成資料生成。講者特別強調蒸餾是一項行之有年、標準的機器學習技術（源自 Hinton 2015 年的論文，有時稱為 model extraction），而非近來流行的「蒸餾攻擊」這種帶有對抗意味的說法。

蒸餾可依四個維度來理解：訊號（在老師輸出的文字上訓練——硬標籤——或在完整 logit 分佈上訓練——軟標籤，後者攜帶更豐富的資訊，說明哪些 token 是有可能但未被選中的候選）；資料來源（白盒可存取 logits 與生成過程，黑盒僅能取得文字）；時序（離線指老師資料在訓練開始前就已生成，線上指老師模型參與訓練迴圈）；以及策略（off-policy 是在老師自身的軌跡上訓練，on-policy 是在學生自己生成、再由老師評分的軌跡上訓練）。講者用西洋棋的比喻說明為何 on-policy 重要：RL 只在對局結束時給出稀疏獎勵，若模型連合法的第一步都下不出來便永遠拿不到訊號；off-policy 蒸餾（如在老師軌跡上做 SFT）訊號較密集，但若老師（大師級棋手）從未遇到學生實際卡關的情境，訊號可能不相關；on-policy 蒸餾則透過評分學生自己的嘗試，同時兼顧密集與相關兩項優點。

在 TRL 中，單一一個類別——實驗性的 Generalized Knowledge Distillation（GKD）Trainer——透過兩個旋鈕同時支援兩種模式：lambda 決定訓練資料來源（0 為 off-policy，使用固定的老師資料；1 為 on-policy，使用學生自行生成的資料），beta 決定 KL 方向（0 為對老師完整分佈取正向 KL；1 為聚焦老師最高機率選擇的反向 KL）。off-policy 的示範重現了前一場的程式碼代理人實驗，但把 SFT 換成序列／logit 知識蒸餾：指示一個程式碼代理人在同一組 Pi 程式碼軌跡資料集上，以 4B 教師模型蒸餾出 0.6B 學生模型，透過 HF Jobs 掃描不同學習率，所有腳本、模型與 Trackio 儀表板都整理成一個 Hub collection 公開。

On-policy 蒸餾源自 DAGGER 論文，也用於近期的前沿模型（GLM-5.2、Qwen3、DeepSeek）。其迴圈為：從學生取樣一段生成內容，將這些 token 送入凍結的老師模型做一次便宜的 prefill 前向傳遞取得逐位置分佈，計算學生與老師之間逐 token 的反向 KL 損失，再更新學生模型。反向 KL 是「找眾數（mode-seeking）」而非正向 KL 的「找均值（mean-seeking）」：後者可能把學生拉向老師分佈的平均值，而這個平均值未必對應老師實際做過的任何事；前者則會把學生推向最能代表老師實際行為的高機率區域。在 TRL 中這正是同一個 GKD Trainer，只是把 lambda 設為 1、beta 設為 1；中間值可以混入部分 off-policy 曝光或緩和找眾數的傾向，但建議先從 0/1 這兩個極端值入門。同樣的實驗設定（0.6B 學生、4B 教師、Pi 程式碼軌跡、三種學習率）也以 on-policy 方式重跑一次，並用 Trackio 記錄結果比較。

最後一段講自我蒸餾（self-distillation），此時「老師」是同一模型的較早版本或具有特權資訊的版本，TRL 支援三種變體。簡單自我蒸餾（SDFT 風格）用來恢復訓練後期流失的能力——例如著重程式碼的微調使指令遵循能力下滑後，可從仍具備該能力的較早 checkpoint 蒸餾回來，這使得 checkpoint 管理成為訓練流程的核心。SDPO（self-distillation policy optimization）為同一任務生成兩段軌跡，第二段給予特權資訊或環境回饋（例如長時間搜尋後才找到的解答，或工具／環境回饋），讓模型學會更快達成好結果，損失計算方式與前述相同，只是在這兩段軌跡之間計算。SDFT（self-distilled fine-tuning）則是在一組取樣結果中，挑選表現最好的那些來訓練。這與 RL（例如 process-reward 方法）之間的界線其實相當模糊，實際的訓練流程——文中以 Nemotron 3 的後訓練章節為深入案例——會混合蒸餾與 RL 技術，並跨多個領域專精 checkpoint 組合出最終模型。

on-policy／off-policy 蒸餾的根本上限是老師本身的表現，因為學生被拉向老師；自我蒸餾則可能超越先前的 checkpoint，因為它借助的是特權資訊或更早的能力，而非外部老師的天花板。RL 的上限則取決於環境與獎勵設計，這也是系列下一場的主題。觀眾問答涵蓋了多教師 on-policy 蒸餾（TRL 未原生支援，但可自行擴充實作，部分前沿實驗室已在使用）、無法對封閉、僅提供 API 的教師模型做 on-policy／基於 logit 的蒸餾（僅能做離線、基於文字的蒸餾，或另外搭配合成資料生成加評審的流程，如 Deita、WizardLM 背後的做法），以及更廣泛的一點：實務中的訓練流程會自由混合各種 checkpoint 與演算法——蒸餾、SFT、RL——而非遵循單一固定食譜。
