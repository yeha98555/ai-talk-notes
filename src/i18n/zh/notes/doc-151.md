---
title: SimulationMaxxing:Nubank 如何將 Agent 出貨速度提升 20 倍
speaker: Aman Gupta, Nubank 與 Shreya Rajpal, Snowglobe
---
Nubank 是拉丁美洲最大的數位銀行,服務巴西、墨西哥與哥倫比亞共 1.35 億名客戶,單季營收超過 50 億美元。其客服模式結合人工客服與 AI agent,講者一開場便展示成果:五個上線中的 AI agent 的 TNPS(客戶滿意度指標)在數季間持續攀升,許多 agent 已逼近甚至超越人類水準。這些進步背後的核心機制其實很簡單:在模擬(simulation)中產生評測資料,而非等待正式環境資料,可以讓團隊出貨速度提升約 20 倍。

論點的起點在於為何評測(eval)才是 agent 開發真正的瓶頸。評測可拆解為兩個要素——指標(metrics)與資料(data)。指標相對容易處理,團隊已有一套可行做法,利用 LLM-as-judge 分類器對齊人類判斷,再透過自動化 prompt 優化持續精進。真正困難的是資料,而這在 agent 時代變得更加棘手。過去傳統機器學習與單輪對話機器人的資料還能視為結構化的列,如今單一 agent 資料點卻是一整條多輪軌跡,內含多次工具呼叫與必須全程保持一致的狀態——生成成本高,擴展成具代表性的樣本集更是難上加難。

團隊取得評測資料通常有兩種方式,但都很痛苦。人工撰寫極為耗時:必須手動規劃軌跡與狀態更新,並確保每次工具呼叫間保持一致。正式環境的追蹤紀錄(production traces)幾乎是免費取得,但代價是要在真實使用者身上進行測試,這使得大規模平行實驗變得危險又困難。實務上,更動 agent 的架構、提示詞或工具或許只需幾小時,但在人工整理的資料上跑離線評測可能要花上數天,而要靠正式環境的 A/B 測試——等待稀疏又嘈雜的客戶回饋——確認真正的改善,則可能要耗費數週甚至更久。

Snowglobe 提供的模擬方案號稱能將這條時間線壓縮到數小時甚至數分鐘。技術上,做法是透過 SDK 包裹目標 agent(無需改動程式碼),辨識哪些工具需要被 mock,接著定義如何引導模擬——包括要產生哪些人物誌(persona)、使用情境與案例。輸出結果是數千則針對真實 agent 的多輪對話資料集,內含 mock 的工具呼叫與一致的合成狀態,並直接餵入評測流程,產出逐輪的評判分數。舉例來說:一個合成人物誌(34 歲的設計師,首次申辦信用卡)會搭配一致的背景資料——虛構地址、虛構信用卡資訊、語氣與互動風格——再讓其與 agent 互動,產出完全符合該人物誌意圖的完整對話,過程中工具呼叫與帳戶資料始終保持一致。

這套機制驅動出一個自我改進循環:上線 agent、觀察表現、建立穩健的評測(常搭配類似 DSPy 的自動化 prompt 優化演算法)、執行模擬、將模擬與真實資料一併餵入評測取得豐富訊號、優化架構、驗證後再次上線——使得每個 agent 能執行遠多於以往的 A/B 測試。為了信任這套循環,團隊驗證了模擬資料與正式環境資料的一致性:模擬評測分數與真實評測分數的相關性很高,人類領域專家審查也證實約 80% 的模擬標註結果可用,無論是成熟 agent 或全新建置的 agent 皆然。

具體成果隨之而來。模擬曾攔截一次原本可能上線的回歸問題,也標記出一項會損害自助服務率的問題。某個 agent 的 TNPS 在採用模擬驅動的系統化迭代後翻倍,而非仰賴反覆試錯。團隊現在會先透過模擬反覆嘗試各種方案,滿意後才啟動一次 A/B 測試,而非直接投入五、六次測試。模擬也讓 Nubank 在不犧牲滿意度的情況下,將自助服務率提升最多 4%——這通常被視為客服領域中的取捨難題。此外,模擬讓團隊能快速將新發布的開源模型與現有 agent 架構進行基準測試,原本可能耗費數週的評估工作因此大幅節省。

結尾的重點是:在模擬中產生評測資料,而非單純仰賴正式環境資料,能打破出貨速度的瓶頸;透過離線/線上/人工審查的比較來縮小模擬與真實之間的落差,是信任模擬結果的關鍵;而最終,打造真正能自我改進的 agent,取決於是否擁有對齊良好的指標,以及能穩定產生資料供這些指標評分的方法——這正是建構持續改進循環的關鍵組合。
