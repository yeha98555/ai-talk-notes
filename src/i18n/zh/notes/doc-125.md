---
title: 當每一秒都至關重要：AI 系統的即時分析
speaker: M，Apache Doris（PMC）
---
這場演講主張，AI 代理正逐漸成為分析系統的主要使用者，這個轉變迫使我們重新思考「即時」分析基礎設施究竟需要提供什麼。

演講從延遲預算談起。一次代理互動可能需要多次檢索呼叫才能產生答案——擷取上下文、呼叫工具、評分，然後回覆。如果每次檢索耗時 200 毫秒，五次加總約一秒，使用者仍會覺得反應迅速；但若每次耗時 3 秒，同樣的一輪互動就會拉長到 15 秒，使用者便會放棄該次對話。因此延遲不是後端細節,而是直接決定產品體驗的關鍵因素。

演講將代理時代對分析工作負載的改變歸納為三個面向：數量、來源與形態。數量大幅上升，因為單一代理互動觸發的請求量遠超過人類分析師一天所發出的量。查詢來源從人類點擊 BI 儀表板轉為代理隨時以程式化方式發出請求。查詢的形態也從少數幾個沉重的多表連接分析查詢，轉變為在單次互動中混合大量小型點查詢、篩選、關鍵字搜尋與向量檢索。這些變化共同使得低延遲、高併發與混合檢索成為基本需求，而非錦上添花的功能。

Apache Doris 被介紹為一個開源、基於 MPP 架構的即時 OLAP 資料庫，具備混合服務能力：它能在單一引擎、單一查詢中同時執行結構化 SQL 分析、全文/關鍵字搜尋與向量檢索，而不需將多個系統拼接在一起。它既支援將資料載入內部儲存以取得更佳效能，也支援直接原地查詢 Iceberg、Delta Lake、PostgreSQL、Elasticsearch 等外部來源，無需先行匯入。在現代資料架構中，它位於上游資料來源（資料庫、串流、資料湖）與下游消費者（BI 工具、AI 代理、MCP 伺服器、Grafana 或 Langfuse 等可觀測性平台）之間。

演講將代理導向分析所需的能力歸納為五大支柱。第一，快速可靠的資料注入：透過 Kafka 或 CDC 持續串流、支援可變（而非僅可附加）資料以便更新記錄而不損失查詢效能，並能吸收注入尖峰而不遺漏資料——並輔以工作負載/資源隔離,避免某一使用者的負載拖累其他使用者。演講展示的基準測試顯示，在高頻更新場景下比 ClickHouse 快達 40 倍。第二，高併發下的次秒級查詢，透過向量化執行、完整 MPP 架構支援複雜連接、豐富的次級索引（倒排、排序、篩選）、分區裁剪、熱資料快取與管線化執行實現——據稱單節點可支撐約一萬 QPS。第三，單一引擎內的混合檢索：結合結構化篩選/聚合、以 BM25 評分的全文搜尋、向量相似度檢索與倒數排名融合，讓代理無需分別查詢三套系統（OLAP 資料庫、搜尋引擎、向量資料庫），從而避免延遲與故障面三倍放大。第四，資料湖整合：透過多目錄框架直接查詢資料湖（Iceberg、Delta Lake 等），支援 Iceberg 表生命週期操作，並以物化視圖加速資料湖查詢——避免資料複製、過時與資料孤島問題，同時讓運算與儲存能各自獨立擴展。第五，面向代理的服務能力：提供大型語言模型可讀的結構定義（欄位註解、表格描述、語意標籤）以提升 text-to-SQL 準確度，提供超越單純 SQL/JDBC 的可程式化介面，例如 CLI 工具、skills 與類 MCP 協定，以及——最關鍵的——可插拔的授權、身分驗證與稽核機制，因為擁有資料庫存取權的代理若無防護，可能執行諸如清空資料表之類的破壞性操作。

演講提供兩方面的基準測試結果：標準分析基準（Star Schema Benchmark、TPC-DS）顯示 Doris 在複雜多表連接上優於 Snowflake、ClickHouse 等替代方案（其中 ClickHouse 據稱未能完成部分 TPC-DS 查詢）；以及更貼近真實代理工作負載的「代理日誌」基準——涵蓋日誌、追蹤與 JSON 負載——顯示 Doris 領先 OpenSearch、Elasticsearch 與 PostgreSQL，尤其在搜尋、分析彙總與半結構化 JSON 處理混合出現時表現特別突出。

演講最後將 Doris 定位為一個活躍發展中的開源專案（超過 700 位貢獻者），在運算、視覺化與資料湖工具方面擁有豐富整合，並可部署於各大雲端平台，並邀請聽眾透過其社群與文件進一步探索。
