---
title: CrabRAG：自動化助理需要的是圖記憶，而非更多 token
speaker: Stephen Chin, Neo4j
---
這場演講以吉祥物「Crab D」開場——一隻用心良苦卻每晚忘光一切、老是拿錯工具的個人助理。這個玩笑點出了嚴肅的重點：隨著 agent 承擔越來越多自主、長時間運行的工作，瓶頸不在於智能，而在於記憶——也就是哪些東西被放進 context、又能從中被回想起來。

對現有做法的檢視，從最簡單的方式開始：把記憶存成純 markdown 檔案，這是 OpenClaw 等工具採用的模式，包含每日記憶檔、工具檔和技能檔。Markdown 對人類可讀、也容易壓縮，但 agent 最終會把所有東西都載入，賭某個東西可能派得上用場——一般 session 每輪就要吃掉超過 10 萬個 token。在小規模、搭配強模型時這行得通，但隨著範圍擴大就會崩潰，因為這種做法重複又浪費 context，而非鎖定真正相關的內容。

以技能為基礎的系統，如 Hermes agent，做法更進一步：agent 在每個任務結束後反思，更新或新增技能——但技能本質上仍是 markdown 檔案，整套系統能否運作，取決於是否載入了正確的技能。選錯技能，或在技能鏈中漏掉必要的一步，agent 就會卡在人類根本不會卡住的地方。演講中提到一個研究方向——把技能建模成圖——作為解決這種技能串接問題的一種方式。

以 MCP 為基礎的記憶系統，如 Goose 專案（屬於新成立的 Agentic AI Foundation）,把記憶當作另一個可插拔的伺服器：透過指令來記住、擷取、遺忘，背後仍是磁碟上的檔案。這增加了彈性，但沒解決根本問題——記憶依然是磁碟上的 markdown，容易變得龐雜，而且因為「遺忘」現在真的是一個 MCP 工具呼叫，agent 隨時可能一個錯誤呼叫就把自己的記憶清空。

向量資料庫是再進一步的做法：把所有東西做成 embedding，存進 pgvector 或 LanceDB 之類的系統，再用相似度做檢索。這能進一步擴大規模，也能拉回真正相關的資訊，但向量空間中的相似性並不等於實際的關聯性。結果就是容易產生幻覺，尤其在需要把多個事實串連起來推理的多跳（multi-hop）問題上——單靠向量搜尋無法可靠地完成這種推理，表面相似的事實會被當成正確答案檢索出來。

圖（graph）正是針對這個問題而生：實體成為一級節點（node），關係成為邊（edge），屬性（包括 embedding）可以附加在節點或邊上，讓向量檢索與圖檢索得以結合。示範中的架構先用向量搜尋找出種子節點，再從這些種子向外做圖遍歷，依照相關性為鄰居節點排序，藉此組合出精確的多跳答案。這樣做的成果是準確性、可解釋性（你能檢視是哪張圖產生了這個答案）以及可稽核性（你能看清楚是哪個子圖餵進了 context）——而且 Claude 相當擅長寫出所需的 Cypher 查詢與實體抽取，開發者不必是圖資料庫專家也能上手。

為了驗證這套做法，講者把自己家中的家庭實驗室網路完整建成一個數位分身圖，使用 Cognee（一家以 Neo4j 為後端的新創公司），並用同一份來源 markdown 建立了對等的向量資料庫版本，兩者都切斷了即時網路存取，答案只能純粹來自記憶。當被問到有哪些過時、暴露在 WAN 上的軟體時，以向量為基礎的 agent 給出了模糊的無效回答；以圖為基礎的 agent 則正確地從種子節點經過一跳鄰居，準確找出那台過時且暴露在網際網路上的伺服器。第二個關於暴露 0.0.0.0 管理埠的查詢也呈現同樣的模式：向量 agent 把工作丟回給使用者，而圖 agent 直接沿著路由器節點找到那兩個真正暴露在外的服務。

結語聚焦於規模：一個四節點的家庭實驗室只是玩具案例，但擁有大型資料中心、或需要處理大量客戶／金融資料且無法塞進百萬 token context 視窗的企業，需要比 markdown 檔案更好的記憶系統。演講最後提到即將出版的新書《GraphRAG: The Definitive Guide》，內容涵蓋圖記憶與 agent 架構在各產業的應用案例，並推薦 Neo4j 免費的 GraphAcademy 課程作為入門資源，內容涵蓋 agent 記憶與 context graph。
