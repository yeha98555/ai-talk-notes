---
title: 評測的未來：從 LLM as a Judge 到 Agent as a Judge
speaker: Aparna Dhinakaran, Arize AI
---
這場簡短的演講主張，隨著 Agent 變得越來越複雜，那些為上一代 LLM 應用打造的評測方法已經不再夠用——並提出 agent-as-judge 作為下一步，與現有方法並行，而非取而代之。

Arize 的觀察視角來自於在許多生產團隊中大規模運行評測：每月超過一億次評測、每個團隊平均 12 個評測工作，頂尖團隊運行的獨立評測器數量高達 3,800 個以上。演講主張，最有價值的訊號並非來自離線評測、甚至也不是標準的線上評測，而是來自持續在真實生產 trace 上運行的評測——這才是真正能揭示哪些東西有效、抓到失敗、並餵入持續學習迴圈的方式。業界普遍同意評測很重要，Anthropic、OpenAI 等公司的領導者都把它視為根本要素。

問題在於，被評測的對象本身已經在評測器底下悄悄變了。2023 年，系統只是回答提示（prompt）。到了 2024 年，前沿模型加入了工具呼叫、推理與深度研究能力。現在，團隊在真實世界資料上運行迴圈，並啟動子 Agent 去處理長時程任務。每一次躍進都不只是變得更難——而是變成了一種不同性質的問題，失敗模式也隨之改變。Arize 自家的內部 Agent「Alex」正好說明了這一點：隨著它獲得更長的記憶、動態 UI 生成能力，以及在龐大 trace 量中搜尋的能力，它也開始出現遺忘上下文、追蹤不到任務是否完成、以及卡在迴圈裡的問題。建立在固定評分標準（rubric）與確定性流程之上的傳統 LLM-as-judge 評測，並非為了抓住這種動態、trajectory 層級的失敗而設計——尤其當每一次使用者互動都會產生真正不同的執行路徑時，更是如此。

提出的解方是 agent-as-judge：用一個 Agent 去評測另一個 Agent，讓分析可以是適應性、動態的，而不是照著固定的評分標準打分。這並不是要取代確定性評測或傳統的 LLM-as-judge 方法——而是新增第三種工具，用來處理另一類問題。今天大多數團隊只依賴前兩種；這場演講的主張是，評測的未來需要三者合力並用。

Arize 對這個想法的具體實作是 Signal，一個長時間運行的 Agent，它讀取 trace、發掘問題的模式，並識別出固定評分標準的評判者絕不會抓到的細微失敗模式——例如某個 Agent 反覆在迴圈中呼叫同一個工具、或走上一條沒效率的執行路徑。因為 Signal 執行的是這種更深入的分析，它能做的不只是標記問題：它還能開一個 pull request，提出修正方案。
