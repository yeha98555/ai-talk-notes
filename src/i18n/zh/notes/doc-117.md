---
title: 訓練 Agent 系列直播教學：如何微調程式碼 Agent 以實現持續學習
speaker: Ben Burtenshaw, Hugging Face
---
這是「訓練 Agent」系列的第一場直播，核心概念本身就頗具後設意味：主講人不是手寫訓練腳本，而是把一個高階提示交給一個 coding agent（Codex）——用 SFT 在特定資料集上訓練一個小型 Gemma 模型、透過 Hugging Face Jobs 進行參數掃描、用 Trackio 追蹤所有指標、推送 adapter、執行評測並更新 model card——接著由人類在旁監督，觀察這個 agent 如何規劃、驗證並執行整條訓練流程。

訓練資料是一份公開的真實 agent trace 資料集，取自 Mario Zechner 的 Pi harness，其中記錄了 Claude Opus 4.5 執行任務的過程：具有分支的多輪工具呼叫、思考步驟與工具回傳結果，且發佈前已清除機密資訊。這個練習的目標並非一次就打造出功能完整的 coding agent，而是讓一個已具備指令遵循能力的小型 Gemma 模型，學會「說 agent 的語言」——也就是模仿該 harness 發出正確的工具呼叫並遵循相同的多輪對話結構——單純使用 SFT，尚未引入獎勵函式或 RL 環境；那些將留待後續探討 GRPO 與 RL 環境的場次。

在真正花費運算資源之前，agent 被賦予了一份「合約」：先閱讀文件、把模型名稱解析為正確的 Hugging Face ID、實作或設定訓練腳本、執行 smoke test 以提早抓出授權、格式或記憶體不足等問題，確認無誤後才以獨立的 HF Jobs 啟動完整的超參數掃描（學習率、LoRA rank、序列長度），並將每次執行統一記錄到同一個 Trackio 專案中。這整套行為是由一組自訂的「skills」——描述如何一致地使用 TRL、HF Jobs 與 Trackio 的 markdown 檔——引導而成，agent 會在行動前先把這些內容讀入 context，團隊也可以根據 agent 常犯的錯誤持續改進這些 skills。

對 SFT 本身的講解則為整套自動化提供了理論基礎：SFT 本質上是預訓練「預測下一個 token」的延續，只是套用在 prompt–completion 配對（也就是 trace）上，而非任意文字，其中最關鍵的差異在於遮罩機制——用像 -100 這樣的標記把使用者那一輪的 loss 歸零，讓模型只學習重現助手的回覆，而非提示本身。這個透過 chat template 與 tokenizer 實現的遮罩過程，被視為即便交由 agent 全權主導訓練，人類仍不可或缺的那一份機制性理解。

由於 SFT 本質上是一種模仿，這個訓練出來的小模型不可能超越它所模仿的教師 trace 的品質，其通用能力甚至可能因此下滑；它真正能做到的，是在存在良好 trace 的狹窄使用情境（例如 PR 分流）上做到專精，而非成為更強的通才。Trackio 儀表板顯示出正確訓練應有的訊號：loss 下降、token 預測的熵下降、token 準確率上升，以及學習率按排程逐漸衰減，且分別在訓練集與保留集上都有追蹤。

最終評測方面，agent 以獨立的 HF Jobs 搭配 Inspect AI 與 vLLM，在 HumanEval 與 MBPP 上進行評分。主講人特別指出這是流程中較弱的一環：這些基準測試已相當飽和，也不太可能與自訂的 trace 資料集有所對應；實務上更應該針對實際目標使用情境設計專屬基準（藉此觀察其進步），再輔以一個通用的程式碼／工具使用基準（確認整體能力沒有退化），而非直接套用通用的公開基準測試。

本場直播最後指向了幾項配套資源——一篇簡短的 SFT 入門文章、Hugging Face 的 LLM 課程、TRL 文件、已公開的 agent trace、skills репо、訓練資料集，以及訓練出的模型（稍後將公開）——並將這次「在 trace 上做 SFT」的練習定位為訓練 Agent 系列至少三場中的第一場，後續將逐步加入 GRPO 式的 RL 與完整的 RL 環境，朝著打造真正具備持續學習能力的 coding agent 邁進。
