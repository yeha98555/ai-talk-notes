---
title: AI on Your Lakehouse:情境以「形狀」呈現,而非查詢——Zach Blumenfeld, Neo4j
speaker: Zach Blumenfeld, Neo4j
---
這場實作工作坊主張:當組織已經具備 text-to-SQL 與向量搜尋來存取自家的 lakehouse 後,真正的瓶頸不再是資料存取,而是資料的「形狀」。當資料倉儲成長到數百張表、文件庫累積到數百萬份檔案時,若代理人僅擁有相似度搜尋與臨時 SQL,就會變得「自信卻答錯」——找不到正確的 join、漏掉文件,也無法回答諸如「我們哪裡沒有涵蓋到」或「整體資料中反覆出現什麼模式」這類全域性問題,因為證明「不存在」或看見全域模式,恰恰是語意搜尋做不到的事。

工作坊示範的解法,是圍繞 Neo4j 的屬性圖模型(節點、關係、屬性)建構出三種可重複使用的「形狀」的圖形化情境層。第一種是 connections(連結),為結構化資料倉儲建立語意層:一個名為 NeoCarta 的 labs 工具透過 MCP 只把 metadata(表、欄位、主鍵/外鍵 join 路徑)從 BigQuery 拉進圖形資料庫,並不搬移實際資料列。代理人接著讀取這個 metadata 圖,在多張相似表之間建立正確的 join,再執行 text-to-SQL——這是完整資料遷移的更輕量替代方案,畢竟資料遷移常受限於規模、同步成本或安全邊界;Neo4j 較新的「virtual graph」則進一步讓 cipher 查詢直接下推到倉儲 schema 上執行。

第二種形狀是 table of contents(大綱),針對高度交互連結的非結構化文件(手冊、公告、召回通知)。工作坊沒有採用典型 GraphRAG 流程中的 LLM 實體抽取,而是使用完全確定性的載入方式:一棵包含樹(資料庫 → 資料夾 → 文件 → 巢狀章節),外加明確反映原始文件交互引用的「links to」邊,每個節點都賦予階層式 URI。這讓匯入具備冪等性、速度快、且不需 LLM 成本,並讓代理人能夠遍歷指定深度的子樹,或直接跳到某個 URI 並抓取其所有連結對象——這更接近人類翻閱目錄的方式,而非以區塊為單位的檢索。疊加在其上的 Lucene 全文索引(可依 URI 前綴限定範圍,並搭配 LLM 驅動的語意詞擴充以達成跨廠商可攜性)是這種導覽方式的補充,而非取代。

第三種形狀是 themes(主題),透過 Neo4j 的 Graph Data Science 函式庫,單純對文件連結圖執行 Leiden 社群偵測演算法,完全不做 LLM 標註——群集純粹從連結結構中浮現,並標註 conductance 分數(群內緊密度 vs. 群外連結度)與各群中連結度最高的文件。這比微軟 GraphRAG 以 LLM 生成階層式社群摘要的做法更為輕量:完全確定性且成本低,但其品質高度依賴原始文件本身的命名與連結是否完善。Themes 能揭露先前未知的分組(例如所有煞車相關文件自然聚成一群),支援涵蓋缺口或系統性模式等全域性問題。

這三種形狀都透過 skills 檔案,搭配 Neo4j 的 CLI、cipher skill 與 GDS skill 提供給程式碼代理人(Claude Code)使用,確保代理人產生的查詢維持在最新狀態,而非從網路上抓取過時的 Stack Overflow 寫法;講者表示這種 text-to-cipher 體驗比一年前可靠得多。示範的查詢包括:結合全文搜尋、樹狀遍歷與倉儲 join 來為單一維修問題提供依據;運用語意擴充與大綱遍歷的全域性查詢,找出未有文件記載的 DTC 代碼,以及與現場結果矛盾的既定維修程序;以及利用 themes 將文件群集與工單歷史相關聯,量化各主題的涵蓋程度。

整場工作坊反覆出現幾個建模上的判斷取捨:關係名稱刻意保持通用(例如所有包含層級統一用一個「has」),以維持查詢的可管理性,但犧牲了部分語意細緻度;是否要把「零件」這類實體明確建成圖節點,還是讓代理人從文字中自行推論,則取決於領域——在生命科學這類本體論嚴謹的領域中更為重要。此外,這次工作坊刻意不將結構化的 connections 圖與非結構化的文件圖連結起來,以速度與模型無關性換取確定性的交叉引用,並留待未來延伸。整體訊息是:圖形資料庫並非要取代向量或全文搜尋,而是提供一個可導覽、可驗證結構的情境層——大綱用於局部遍歷、themes 用於全域模式發現、connections 用於倉儲層級的 join——這些是純檢索方式本身無法提供的。
