---
title: 為什麼代理式系統需要 Ontology
speaker: Frank Coyle, UC Berkeley
---
這場演講追溯了兩條各自獨立的脈絡——agent 與 ontology——並主張今日的 agentic AI 其實正是兩者的匯流:一個機率性、由 LLM 驅動的迴圈，搭配一套對領域的正式、符號化表徵。Agent 概念可回溯到早期 AI 學者如 McCarthy、Selfridge、Minsky，他們將 agent 定義為能感知、決策並行動的東西。Ontology 則追溯得更早，從亞里斯多德的存在範疇，到 Quine 加以形式化，再到 1993 年 Gruber 給出的定義：對共享概念化的正式規格——這正是我們希望交給 agent 的東西，讓它與我們共享對某個領域的概念模型。這種結合現在被稱為 neuro-symbolic AI：神經網路（LLM）與符號式 AI（規則系統與知識圖譜）相連結，演講的核心主張是，正是這層符號結構讓本質上機率性、容易產生幻覺的 LLM 保持在可控軌道上。

Ontology 本身並不神秘：它就是實體、實體間關係、以及實體屬性所構成的圖。它之所以興起，是因為關聯式資料庫過於僵化——新增一個屬性就得重構整個資料表，而圖結構只需新增一個節點或一條邊即可。建構 ontology 可以由上而下，讓領域專家坐下來定義實體與關係（這正是 1980 年代 expert systems 熱潮與後續泡沫破裂所走的路線，直到 GPU 讓神經網路變得可行之前一直無法規模化）；也可以由下而上，從真實互動（例如顧客行為）中挖掘值得納入的實體與關係。建構者不必從零開始：既有的分類體系如 schema.org、FOAF（用於社群網路建模）、Dublin Core（用於描述出版品）、以及支撐 Wikipedia 搜尋功能的 DBpedia，都已累積數十年的成果可供沿用。

有了 ontology 之後，RDFS 與 OWL 這類輔助技術可以在原始圖結構之上疊加推論與限制。RDFS 的 domain/range 機制能讓我們從「Bob teaches Scooter」這句話推論出 Bob 是老師、Scooter 是學生。OWL 則加入了如遞移性（transitive，若 Sue 是 Mary 的祖先、Mary 是 Ann 的祖先，則 Sue 是 Ann 的祖先）與函數性屬性（functional property，例如「has father」關係只能有一個值，因此若兩個不同名字都透過此關係連到同一個孩子，就可推知這兩個名字指的是同一個人）等機制。這些推導並不存在於圖結構本身，而是附掛其上，也正是演講中提出用來讓 agent 保持誠實的機制。

談到 agent 迴圈，演講將今日的 agentic AI 放進 Böhm–Jacopini 1966 年的結論脈絡中——循序、條件與迭代三者具備即可使一種語言達到圖靈完備，如今 agent 終於補上了迴圈這一塊，這雖然強大卻也危險：迴圈可能無限執行、可能因 agent 彼此對話而逐漸失控，也會不斷消耗 token 與金錢。透過一段 Claude agent 程式碼範例，演講說明其運作機制：LLM 本身無法執行任何動作，只能提出機率最高的下一段文字，因此在給定工具與提示詞後，它會回傳一個帶有參數的工具呼叫提案；迴圈接著檢查 stop reason，若為「tool use」，該工具才會真正執行。演講提出的介入點，是在工具執行之後、其結果被信任之前，插入一個以 ontology 為基礎的驗證層：Pydantic 負責在「門口」把關輸入參數的型別，ontology 則在「帳本」端檢查回傳結果是否合理，因此理想上 agent 在通過此檢查之前不應產生任何副作用。

幾個具體的 OWL 建構範例，說明了這類推論能捕捉到哪些在純文字情境下很難察覺的錯誤：disjoint properties（互斥屬性）限制可以標記出同一筆訂單被重複退款，或是款項被誤付給客服人員而非買家（因為顧客與客服是兩個互斥的類別）；列舉值限制則能拒絕像「probably shipped」這類幻覺出來的狀態值，因為合法狀態只有已付款、已出貨或已退款。整體建議是把 ontology 視為坐落在 agent 迴圈旁的一個推理器（reasoner）——一種在本質上機率性的流程中加上正式護欄的方法，也呼應了這個領域正重新回顧、但如今擁有更易操作工具的符號式 AI 脈絡。
