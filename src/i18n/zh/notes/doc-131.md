---
title: 打造未來：以 ClickHouse 實現即時、向量驅動的分析
speaker: 開發者關係人員, ClickHouse
---
這場演講說明開源列式 OLAP 資料庫 ClickHouse——原本專為海量資料上的高速分析而生——如何自然而然地成為 AI 與代理式工作負載的基礎設施，並展示 ClickHouse 團隊如何在自家資料庫與 MCP 伺服器之上打造了一個公開的聊天代理。

客戶通常透過兩種途徑走向以 ClickHouse 支援 AI 應用：一是原本就用 ClickHouse 做分析，進而把它挪用於新用途（早期採用者在 ClickHouse 尚未針對此場景優化前就把它當成向量儲存庫使用，這也促使團隊後續投入真正的效能優化）；二是看到同業以 ClickHouse 支援 AI 而跟進採用。演講中反覆出現四種 AI/ML 相關用途：作為特徵儲存庫（feature store）——一組經過整理、去敏處理的資料集，用於模型訓練，刻意剔除敏感或「有毒」資料，避免代理學到不當行為或洩露隱私；用於模型推論，餵入未曾見過的新資料並檢視代理處理是否得當；用於資料探索與準備，也就是訓練前的資料修剪與強化工作；以及作為向量儲存庫，存放向量化資料（技術上是 float32 陣列）以供相似度搜尋——這項測試版功能可依給定向量查詢相似項目，最容易理解的示範是圖片搜尋，但同樣適用於文字。

人與資料庫互動的架構正在轉變。舊模式是一個使用者查詢對應一則 SQL 陳述式與一個結果，中間頂多經過一層薄薄的中介層處理如身分驗證等事務。聊天代理打破了這個模式：使用者的單一提問可能觸發數十次探索性查詢，代理反覆抓取航班資料、天氣資料、行事曆資料等以組合出答案，而查詢速度緩慢會直接拖慢代理的回應能力。這正是 ClickHouse 打造自身參考架構的動機——結合其 MCP 伺服器、公開資料集（英國房價、紐約計程車資料、航班延誤資料），以及 Anthropic 的 Claude 作為對話層，並以公開展示的「Agent House」（llm.clickhouse.com）呈現：它能針對自然語言問題執行多步驟 SQL 查詢並自動產生視覺化圖表。

在可觀測性方面，Anthropic 與 OpenAI 都以 ClickHouse 監控自家 LLM 產品。Anthropic 需要在自有、氣隙隔離（air-gapped）的安全運算環境中，以低營運成本快速攝取來自 Claude 的大量半結構化即時遙測資料，因此選擇在自家環境（而非雲端）部署 ClickHouse，並仰賴動態擴縮與物件儲存。OpenAI 則在 ChatGPT 與企業 API 可觀測性上採用 ClickHouse，起因是像 Ghibli 風格圖片熱潮這類事件造成流量暴增；團隊看重 ClickHouse 的開源特性（他們也曾提交程式碼貢獻回饋社群）、水平擴展能力、雲原生架構、支援多樣查詢型態的彈性索引、原生 SQL，以及在其他大型客戶身上驗證過的可靠性。ClickHouse 在自家公開聊天代理上線後不久遭受攻擊，也套用了同樣的模式為其加上可觀測性，使用 OpenTelemetry 與自家的 ClickStack 可觀測性套件。

支撐這一切的核心是 ClickHouse MCP 伺服器，它實作 model context protocol，讓 AI 模型得以跨出訓練資料範圍，接觸資料庫、API、檔案，甚至智慧家庭裝置等即時系統。最初於（約一月）推出的開源本地版 MCP 伺服器需要手動架設基礎設施，但目前 ClickHouse Cloud 上的全代管版本已進入私有預覽階段：可直接從 UI 啟用、支援 OAuth 驗證、細緻的存取控制，並相容常見的 MCP 用戶端——演示中既展示了針對個人 ClickHouse 資料的獨立聊天介面，也展示了直接整合進 Claude 的用法。ClickHouse 的遠端 MCP 伺服器也已在 AWS Marketplace 的 AI 代理與工具類別中上架。展望未來，一項直接內建於 ClickHouse Cloud 的「Ask AI」功能，將讓非技術使用者（例如行銷部門的人）以純自然語言查詢資料庫而無需撰寫 SQL，並仍受今日保護敏感資料的相同憑證與存取控制規範所約束。
