---
title: Coding Agent 的 Context Engineering
speaker: Fausto, JADS Applied AI Lab
---
開場前提十分直白：模型每週都在變，連打造它們的實驗室也難以解釋其內部運作，因此工程師真正能拉動的槓桿，只有注入 context window 的內容。實務上的經驗法則是：無論視窗是 20 萬還是一百萬 token，都別讓 Claude Code session 用超過約 25% 的 context 預算——超過之後回應會更慢、更貴、也更容易出錯，而且其實有很簡單的結構性解法。

講者將 context 粗分為決定性（deterministic）、機率性（probabilistic）與人為（human）三類。CLAUDE.md（user、project、子資料夾層級）在每個預設 agent session 都會被決定性載入，但很容易膨脹，因此 coding 慣例更適合放在以路徑或副檔名為範圍的 rules 檔。Hooks 掛在生命週期事件上——例如改寫使用者輸入，或在 session 結束時做後處理——對修正模型版本升級帶來的行為漂移特別有用。Claude 內建的 auto-memory 是一套 markdown 儲存，但仍不太懂得該存什麼、何時取用。排程迴圈（類 cron 的重複執行）則留給 token 預算充裕的團隊。

機率性這一側，sub-agent 不會繼承 CLAUDE.md、memory 或預設人格，因此把非編碼工作（發票、郵件、研究）交給專用 sub-agent，能讓主要的 coding agent 保持專注。Skills 本質上就是背後接一份 markdown 指示檔的 slash command，還可以包 script、甚至包其他模型——例如在 Claude 裡呼叫一個處理原生影片的 Gemini sub-agent。比任何從市集下載的 skill 更重要的是「做 skill 的 skill」（社群 skill 請自負風險）：聊天中解完一個問題後，一句「把它做成 skill」就能把成果變成可重用資產，而不是散落在資料庫與各處的 markdown。當累積到數百個 skills、rules、sub-agents 與略嫌肥大的 CLAUDE.md 時，deferred tools（只要一個設定旗標）能讓描述在需要前不佔用視窗；但過度壓縮描述會讓模型缺乏挑選 skill 的依據，建議 user 層級保持精簡，在個別專案才載入完整的 skill 與 MCP 描述。

人的這一層得到的叮嚀是：去讀文件。Anthropic 的文件（以及官網上的文件 agent）是「知道什麼是可能的」的靈感來源，而模型升級不斷改變行為——例如 Opus 4.7 意見很強、完全照你說的做（不見得是好事），也不再輸出推理過程——所以理解概念比記住細節更重要。

整場演講的核心是用大腦類比記憶系統。工作記憶約能容納七件事；我們感知到什麼受先驗（priors）過濾（「你知道什麼，才看得見什麼」）；記憶經海馬迴緩慢固化，且每次被提取都會被改寫。對應到工程上（講者將這個想法歸功於 Andrej Karpathy 的整理），就是用純 markdown wiki 當 agent 記憶：不需要 RAG 管線，原始檔案原封不動保存，由 LLM 整份處理、萃取成概念、實體、程序與程式片段，再以一份索引（可用 Obsidian 視覺化）與一個隨資訊流動即時更新的 hot.md 串起來。其上再疊幾條簡單政策：類 Ebbinghaus 遺忘曲線的衰減規則讓 14–30 天沒被用到的概念分數下降、相關概念反覆出現則分數上升；被指示「全部下載」的研究 sub-agent 只把約 5% 相關內容注入當前視窗，其餘 95% 先存起來備用。Observer sessions——透過 tmux 開的獨立終端機，有自己的 CLAUDE.md、完整索引與「熟讀 wiki」的常駐指令——監看主聊天的 JSONL 逐字稿，發現缺口時把 wiki fetch 推進主 agent 的 context，或反向把新發現寫回 wiki；講者把這種吃 token 的背景處理丟給另一個原本閒置的 Codex 訂閱。

為什麼值得？一場 demo 讓兩個完全相同的 Opus 4.7 環境——相同的 CLAUDE.md、skills、sub-agents——挑戰同一個刻意選得很難的任務（cellular automata 視覺化），並每 30 秒往 session 注入倒數計時。唯一差異是其中一組有事先花一小時研究填好的 wiki。在五分鐘期限下，有 wiki 的那組直接取用概念動手建置；預設那組只能倚賴參數記憶或倉促研究——而演講強調，時間正是最重要的指標。

收尾的論點關於任務挑選：如果你無法判斷模型輸出的好壞，就不該把任務交給 LLM——這排除了寫文章，以及（經濟因素不亞於技術因素的）AI 客服；但可驗證、對人類困難的工作——例如從工程圖中萃取結構化資訊——正是甜蜜點。這個框架也帶出當晚的工作坊挑戰：從 2D 工程圖萃取足以重建 3D 模型的 JSON，55 分鐘建置記憶系統、5 分鐘處理正式圖面——題目刻意選到研究 agent 無法在時限內暴力破解。
