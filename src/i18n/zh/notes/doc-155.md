---
title: 教AI找出真正的漏洞
speaker: David Brumley, Bugcrowd / 卡內基美隆大學
---
這場演講主張,訓練前沿模型駭客技巧的最佳方式,和訓練頂尖人類駭客一樣：透過一套難度遞增的任務階梯，從玩具程式一路推進到強化過的真實世界目標，每一關都搭配一個確定性的評分機制（oracle）。講者以自己一位學生的經歷為例：這位學生從高中的奪旗賽（CTF）出發，兩年內在 Pwn2Own 贏得 37.5 萬美元獎金和一輛 Tesla，靠的正是研讀技術文章、在逐步加難的挑戰上反覆練習——如今這套方法論正被編碼進網路安全的強化學習環境中。

設計這類強化學習環境需要兩個維度：目標難度（玩具程式 → CTF → 合成問題 → 強化過的真實世界目標）與利用難度（找到漏洞 → 觸發當機 → 任意記憶體讀寫 → 完整程式碼執行）。每個環境都把有漏洞的應用程式包在容器中，透過 MCP 暴露 setup／read／write 工具，關鍵是依賴確定性的評分 oracle，而非讓 LLM 當裁判——因為模型幾乎總是會宣稱自己成功了，即使根本沒有真正完成利用。

現有 benchmark（例如 CyberGym 等）的一大陷阱，是假設一個程式只有一個漏洞。但真實軟體幾乎從不是這樣，一旦存在多個漏洞，模型就會透過反覆找到最容易的那個來「獎勵駭客」（reward hack），導致學習停滯不前。若直接告訴模型漏洞確切位置（例如透過堆疊回溯），雖能避免這個問題，卻也完全抹殺了推理的挑戰性，因為模型只需檢視被標記出的函式即可。就連 DARPA 精心策劃、耗資高昂的競賽（Cyber Grand Challenge、AIxCC）都意外在約一半的挑戰中混入了非預期的漏洞，說明手工打造單一漏洞環境根本無法規模化。

解方是所謂的「稽核任務」（audit task）：不再要求模型找出「那個」漏洞,而是要求它找出「所有」漏洞並逐一提交證明。確定性評分器利用堆疊回溯將不同漏洞去重，計算相對於一個可正規化（且可擴充）的真實漏洞集合的精確率與召回率，且從不透露漏洞總數。這樣一來，模型無法靠鎖定最簡單的漏洞來取巧，也能因為找出先前未知的真實漏洞而獲得獎勵，從而在不需要 LLM 裁判的情況下，產生更乾淨的開放世界訓練訊號。

為了測試前沿模型能爬到階梯多高的位置，團隊以 Chrome 的 V8 JavaScript／Wasm 引擎中 41 個真實漏洞建構了 ExploitBench，選擇 V8 是因為其沙箱逃逸具有真正的高價值（懸賞從一萬美元到十萬美元以上不等），且往往需要串連多個漏洞。他們定義了一個 16 級能力階梯——從觸發當機、到沙箱內的任意讀寫、再到沙箱外的操作能力，直到完整的任意程式碼執行。在舊有的「觸發當機即可」指標下，頂尖模型（GPT 與內部模型 Mythos）達到約 95%，就連較弱的模型如 Gemini、Kimi、Minimax、GLM 也有約 50%——這個指標幾乎無法區分模型能力。但在完整沙箱逃逸（任意程式碼執行）上，Mythos 成功率達 73%，GPT 系列約 68%，而 Gemini 和 Kimi 則是 0%——出現了明顯且有意義的區隔。Mythos 的多個利用方案採用了連專家都認為不切實際的創意技巧（例如逆向推導 Math.random 來偽造指標，用於一個返回導向編程攻擊；或在 x86 上找到一條連內部專家都認為不可行的全新 Wasm 利用路徑），顯示這確實是新穎的漏洞利用而非單純記憶。除 Mythos 的紀錄（因保密協議及其利用方式屬未公開的武器化零日漏洞而未釋出）外，其餘環境與對話紀錄皆已在 exploitbench.ai 上以附帶 MCP 介面的 Docker 映像檔形式公開。

展望未來，團隊正大規模挖掘開源軟體中全新的零日漏洞（以確保模型不可能靠記憶取巧），並將其轉化為強化學習環境，每月為合作實驗室提供多達一萬個環境。演講的結論是：訓練模型從事真正的網路安全工作並不神秘，但確實需要真正的領域專家來建構正確的評分機制、審查對話紀錄以偵測獎勵駭客與記憶行為，並在模型發現無人知曉的漏洞的那一刻，有一套原則性的應對方式。
